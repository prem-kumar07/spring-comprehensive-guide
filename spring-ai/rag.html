Spring AI RAG & VectorStore

Spring AI 1.x Spring AI 2.x

Retrieval-Augmented Generation (RAG) is a pattern that grounds an LLM's responses in your own documents and data. Spring AI provides a complete pipeline — from ingesting source documents into a vector store, to wiring retrieval advisors that inject relevant context into every chat prompt. The result is accurate, citable answers from models that have never been trained on your private knowledge.

RAG — Retrieval-Augmented Generation

RAG addresses a fundamental limitation of LLMs: their knowledge is frozen at training time. By pairing any chat model with a vector store, you extend its knowledge base with your own documents — with no fine-tuning required. The pipeline runs in two distinct phases: an offline ingestion phase that indexes your documents, and an online retrieval phase that fetches the most relevant context at query time.

What is RAG and Why Use It

Large Language Models are trained on a fixed corpus with a knowledge cutoff date. They cannot answer questions about your internal documentation, recent events, or private data without being retrained — an expensive and slow process. Retrieval-Augmented Generation solves this by breaking the problem into two phases: ingestion (storing your documents as vector embeddings) and retrieval (finding the most relevant chunks at query time and injecting them into the model prompt as context).

The LLM is then instructed to answer only based on the provided context, which dramatically reduces hallucination and makes answers citable. Spring AI's RAG support covers both phases end-to-end, integrating with 15+ vector store backends and every major embedding provider.

Key RAG concepts

ConceptRole
EmbeddingA dense numeric vector representing the semantic meaning of a text chunk
VectorStoreA database that stores and indexes embeddings for fast similarity search
Cosine similarityMetric used to rank retrieved chunks by relevance to the query embedding
Top-KThe K most similar documents returned from a similarity search
AdvisorSpring AI component that intercepts ChatClient calls to inject retrieved context

Ingestion Phase — Indexing Your Documents

The ingestion pipeline runs once (or on a schedule as your documents change). It reads source documents with a DocumentReader, splits them into overlapping chunks with a TextSplitter, converts each chunk to an embedding vector via EmbeddingModel, and stores both the vector and the original text in a VectorStore. The split step is critical: chunks must be small enough to fit inside the context window but large enough to carry complete concepts.

Example — Full Ingestion Pipeline

import org.springframework.ai.document.Document;
import org.springframework.ai.reader.TextReader;
import org.springframework.ai.transformer.splitter.TokenTextSplitter;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.core.io.ClassPathResource;

@Service
public class IngestionService {

    private final VectorStore vectorStore;

    public IngestionService(VectorStore vectorStore) {
        this.vectorStore = vectorStore;
    }

    public void ingest(String resourcePath) {
        // Step 1: Read
        TextReader reader = new TextReader(new ClassPathResource(resourcePath));
        List<Document> docs = reader.read();

        // Step 2: Split
        TokenTextSplitter splitter = new TokenTextSplitter();
        List<Document> chunks = splitter.apply(docs);

        // Step 3 + 4: Embed and store (VectorStore handles embedding internally)
        vectorStore.add(chunks);
        System.out.printf("Ingested %d chunks from %s%n", chunks.size(), resourcePath);
    }
}

Retrieval Phase — Answering Questions with Context

At query time, the user's question is converted to an embedding using the same EmbeddingModel used during ingestion. A cosine similarity search finds the K most semantically relevant document chunks. Those chunks are formatted as a context block and injected into the model prompt alongside the original question. The model is instructed to derive its answer only from the provided context, reducing hallucination and enabling it to cite sources.

Spring AI's QuestionAnswerAdvisor and RetrievalAugmentationAdvisor automate this retrieval-and-injection step, so you wire the advisor once and every ChatClient call gets RAG automatically.

Example — Query-Time Retrieval Flow

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.ai.vectorstore.SearchRequest;
import org.springframework.ai.rag.advisor.QuestionAnswerAdvisor;

@Service
public class RagService {

    private final ChatClient chatClient;

    public RagService(ChatClient.Builder builder, VectorStore vectorStore) {
        this.chatClient = builder
            .defaultAdvisors(new QuestionAnswerAdvisor(vectorStore,
                SearchRequest.defaults().withTopK(4)))
            .build();
    }

    public String answer(String question) {
        // The advisor automatically:
        // 1. Embeds the question
        // 2. Runs similarity search (top-4 chunks)
        // 3. Injects chunks as context into the prompt
        return chatClient.prompt()
            .user(question)
            .call()
            .content();
    }
}

Document Readers and Transformers

Spring AI's ETL pipeline follows the Extract-Transform-Load (ETL) pattern. Extract with a DocumentReader that understands the source format; Transform with one or more DocumentTransformer implementations that split, enrich, or reformat documents; Load by calling VectorStore.add() which embeds and persists the final document list. Each step returns List<Document>, making the stages composable and independently testable.

TextReader — Plain Text Files

TextReader is the simplest DocumentReader: it reads a Spring Resource (classpath file, file-system path, URL, or any Resource implementation) and returns a List<Document> containing a single Document with all the file's text as its content. Use TextReader for Markdown, plain text, CSV, YAML, or any human-readable format that doesn't require format-specific parsing. The document's metadata automatically includes the resource description.

Dependency (pom.xml)

<dependency>
  <groupId>org.springframework.ai</groupId>
  <artifactId>spring-ai-core</artifactId>
</dependency>

Example

import org.springframework.ai.reader.TextReader;
import org.springframework.ai.document.Document;
import org.springframework.core.io.ClassPathResource;
import org.springframework.core.io.FileSystemResource;

// Read from classpath
TextReader cpReader = new TextReader(new ClassPathResource("docs/faq.txt"));
List<Document> docs = cpReader.read();
// docs.get(0).getText() contains all file content
// docs.get(0).getMetadata() contains {"source": "class path resource [docs/faq.txt]"}

// Read from filesystem
TextReader fsReader = new TextReader(new FileSystemResource("/data/knowledge-base.md"));
List<Document> mdDocs = fsReader.read();

// Typically followed by splitting for large files
TokenTextSplitter splitter = new TokenTextSplitter();
List<Document> chunks = splitter.apply(docs);
vectorStore.add(chunks);

PdfDocumentReader — PDF Files

PdfDocumentReader parses PDF files using the Apache PDFBox library. It produces one Document per page by default, which keeps chunks naturally sized and preserves page number metadata. The PdfDocumentReaderConfig lets you control page splitting, whether to extract images, and how to handle multi-column layouts. PDF metadata (author, title, creation date) is captured in each document's metadata map.

Dependency (pom.xml)

<dependency>
  <groupId>org.springframework.ai</groupId>
  <artifactId>spring-ai-pdf-document-reader</artifactId>
</dependency>

Example

import org.springframework.ai.reader.pdf.PdfDocumentReader;
import org.springframework.ai.reader.pdf.config.PdfDocumentReaderConfig;
import org.springframework.core.io.ClassPathResource;

// Default: one Document per page
PdfDocumentReader reader = new PdfDocumentReader(
    new ClassPathResource("docs/spring-reference.pdf"));
List<Document> pages = reader.read();

// Custom config — split on paragraphs, not pages
PdfDocumentReaderConfig config = PdfDocumentReaderConfig.builder()
    .withPagesPerDocument(1)
    .withPageExtractedTextFormatter(ExtractedTextFormatter.defaults())
    .build();

PdfDocumentReader configuredReader = new PdfDocumentReader(
    new ClassPathResource("docs/annual-report.pdf"), config);
List<Document> docs = configuredReader.read();

// Each document carries page metadata
docs.forEach(doc -> {
    System.out.printf("Page %s: %d chars%n",
        doc.getMetadata().get("page_number"),
        doc.getText().length());
});

TikaDocumentReader — Word, HTML, CSV, and More

TikaDocumentReader uses Apache Tika to extract text from almost any file format: Microsoft Word (.docx), Excel (.xlsx), PowerPoint (.pptx), HTML, RTF, EPUB, CSV, and dozens more. This makes it the Swiss-army reader for heterogeneous document collections. Tika auto-detects the content type from the file bytes, so you don't need to specify the format. The dependency pulls in Tika's full set of parsers.

Dependency (pom.xml)

<dependency>
  <groupId>org.springframework.ai</groupId>
  <artifactId>spring-ai-tika-document-reader</artifactId>
</dependency>

Example

import org.springframework.ai.reader.tika.TikaDocumentReader;
import org.springframework.core.io.ClassPathResource;
import org.springframework.core.io.FileSystemResource;

// Read a Word document
TikaDocumentReader wordReader = new TikaDocumentReader(
    new ClassPathResource("reports/quarterly-review.docx"));
List<Document> wordDocs = wordReader.read();

// Read an HTML file — Tika strips tags, returns clean text
TikaDocumentReader htmlReader = new TikaDocumentReader(
    new ClassPathResource("content/article.html"));
List<Document> htmlDocs = htmlReader.read();

// Read an Excel spreadsheet
TikaDocumentReader xlsxReader = new TikaDocumentReader(
    new FileSystemResource("/uploads/data-export.xlsx"));
List<Document> xlsxDocs = xlsxReader.read();

// All readers return List<Document> — uniform downstream processing
List<Document> allDocs = new ArrayList<>();
allDocs.addAll(wordDocs);
allDocs.addAll(htmlDocs);
allDocs.addAll(xlsxDocs);

TokenTextSplitter splitter = new TokenTextSplitter();
vectorStore.add(splitter.apply(allDocs));

TokenTextSplitter — Chunking Documents

TokenTextSplitter divides large documents into overlapping chunks measured in tokens (using a CL100K tokenizer compatible with OpenAI models). The default chunk size is 800 tokens with a minimum chunk size of 350 characters. Overlapping chunks ensure that sentences spanning a chunk boundary appear in both adjacent chunks, preserving semantic continuity. TokenTextSplitter implements DocumentTransformer, so it can be applied as a function: splitter.apply(docs) or used in a transformer chain.

Example

import org.springframework.ai.transformer.splitter.TokenTextSplitter;

// Default configuration: 800 tokens, 350 min chars, overlap enabled
TokenTextSplitter defaultSplitter = new TokenTextSplitter();
List<Document> chunks = defaultSplitter.apply(docs);

// Custom configuration
TokenTextSplitter customSplitter = new TokenTextSplitter(
    500,   // defaultChunkSize — tokens per chunk
    100,   // minChunkSizeChars — minimum characters to keep a chunk
    5,     // minChunkLengthToEmbed — minimum characters to embed at all
    10000, // maxNumChunks — safety cap
    true   // keepSeparator — preserve sentence-ending punctuation
);

List<Document> smallChunks = customSplitter.apply(docs);
System.out.printf("Split %d docs into %d chunks%n", docs.size(), smallChunks.size());

// Chunks inherit metadata from parent document
smallChunks.forEach(chunk -> {
    // chunk.getMetadata() contains parent doc metadata + chunk index
    System.out.println(chunk.getMetadata());
});

KeywordMetadataEnricher — Tagging Documents

KeywordMetadataEnricher is a DocumentTransformer that calls an AI model to extract keywords from each document chunk and stores them in the document's metadata under the "excerpt_keywords" key. This enriches chunks with extractive keyword metadata that can later be used for hybrid search (keyword + vector) or metadata filtering. The enricher makes one LLM call per document, so use it selectively on important collections where keyword precision matters.

Example

import org.springframework.ai.transformer.KeywordMetadataEnricher;
import org.springframework.ai.chat.model.ChatModel;

// KeywordMetadataEnricher calls the ChatModel to extract keywords
KeywordMetadataEnricher enricher = new KeywordMetadataEnricher(chatModel, 5);

// Apply as a DocumentTransformer
List<Document> enrichedDocs = enricher.apply(chunks);

// Each document now has keyword metadata
enrichedDocs.forEach(doc -> {
    String keywords = (String) doc.getMetadata().get("excerpt_keywords");
    System.out.println("Keywords: " + keywords);
    // e.g. "Keywords: Spring AI, embeddings, vector store, RAG, retrieval"
});

// Chain reader → splitter → enricher → store
List<Document> pipeline = new TextReader(resource).read();
pipeline = new TokenTextSplitter().apply(pipeline);
pipeline = enricher.apply(pipeline);
vectorStore.add(pipeline);

Vector Store Backends and Search API

A VectorStore stores document embeddings and answers cosine similarity queries. Spring AI defines a uniform VectorStore interface with two primary operations: add(List<Document>) for ingestion and similaritySearch(SearchRequest) for retrieval. Switching vector store backends requires only a Maven dependency swap and updated connection properties — no application code changes.

SimpleVectorStore — In-Memory / Development

SimpleVectorStore is a pure-Java in-memory vector store backed by a ConcurrentHashMap. It computes cosine similarity in memory on every search. No external infrastructure is required, making it ideal for local development, integration tests, and prototyping RAG pipelines before choosing a production store. The store can optionally be persisted to a JSON file on disk and reloaded on startup to avoid re-ingesting documents every run.

Dependency (pom.xml)

<dependency>
  <groupId>org.springframework.ai</groupId>
  <artifactId>spring-ai-core</artifactId>
</dependency>
<!-- EmbeddingModel required — e.g. OpenAI -->
<dependency>
  <groupId>org.springframework.ai</groupId>
  <artifactId>spring-ai-openai-spring-boot-starter</artifactId>
</dependency>

Example

import org.springframework.ai.vectorstore.SimpleVectorStore;
import org.springframework.ai.embedding.EmbeddingModel;

@Configuration
public class VectorStoreConfig {

    @Bean
    VectorStore vectorStore(EmbeddingModel embeddingModel) {
        return SimpleVectorStore.builder(embeddingModel).build();
    }
}

// Usage in a service
@Service
public class SimpleRagService {

    private final VectorStore vectorStore;

    public SimpleRagService(VectorStore vectorStore) {
        this.vectorStore = vectorStore;
    }

    public void ingest(List<Document> docs) {
        vectorStore.add(docs); // embeds and stores in memory
    }

    public List<Document> search(String query) {
        return vectorStore.similaritySearch(
            SearchRequest.query(query).withTopK(4));
    }
}

// Persist to disk and reload
SimpleVectorStore store = SimpleVectorStore.builder(embeddingModel).build();
store.add(docs);
store.save(new FileSystemResource("/tmp/vector-store.json"));

// Next startup — reload without re-ingesting
SimpleVectorStore reloaded = SimpleVectorStore.builder(embeddingModel).build();
reloaded.load(new FileSystemResource("/tmp/vector-store.json"));

SearchRequest — Controlling Similarity Search

SearchRequest is the query object passed to VectorStore.similaritySearch(). It encapsulates the query text, the maximum number of results (topK), a minimum similarity score threshold, and an optional metadata filter expression. Raising the similarity threshold improves precision at the cost of recall. The threshold is expressed as a cosine similarity score between 0.0 and 1.0; 0.75 is a common starting point.

Example

import org.springframework.ai.vectorstore.SearchRequest;
import org.springframework.ai.vectorstore.filter.FilterExpressionBuilder;

// Minimal request — top-4, no threshold
List<Document> results = vectorStore.similaritySearch(
    SearchRequest.query("How does Spring AI handle embeddings?")
        .withTopK(4));

// With similarity threshold — only high-confidence matches
List<Document> highConf = vectorStore.similaritySearch(
    SearchRequest.query("What is the default chunk size?")
        .withTopK(5)
        .withSimilarityThreshold(0.75));

// With metadata filter — limit to one category
FilterExpressionBuilder b = new FilterExpressionBuilder();
List<Document> filtered = vectorStore.similaritySearch(
    SearchRequest.query("deployment configuration")
        .withTopK(3)
        .withSimilarityThreshold(0.70)
        .withFilterExpression(b.eq("category", "devops").build()));

// SearchRequest.defaults() — uses topK=4, no threshold
List<Document> defaults = vectorStore.similaritySearch(
    SearchRequest.defaults().withQuery("Spring AI configuration"));

Retrieval Advisors and Query Pipeline

Spring AI provides two retrieval advisors that plug into ChatClient via .defaultAdvisors(). QuestionAnswerAdvisor is the quick-start option: one line of code wires RAG into any chat call. RetrievalAugmentationAdvisor is the modular option: its builder accepts pluggable query transformers, document retrievers, and document rankers, enabling advanced patterns without changing advisor source code.

QuestionAnswerAdvisor

QuestionAnswerAdvisor is the primary RAG advisor in Spring AI 1.x and 2.x. It intercepts every ChatClient call, extracts the user's question, runs a VectorStore.similaritySearch() with the configured SearchRequest, formats the retrieved chunks as a context block, and prepends them to the system prompt. The default context template instructs the model to answer strictly from the provided context and to say "I don't know" when the context is insufficient.

Example

import org.springframework.ai.rag.advisor.QuestionAnswerAdvisor;
import org.springframework.ai.vectorstore.SearchRequest;

@Service
public class RagChatService {

    private final ChatClient chatClient;

    public RagChatService(ChatClient.Builder builder, VectorStore vectorStore) {
        // Wire once at construction — applies to every call on this client
        this.chatClient = builder
            .defaultAdvisors(
                new QuestionAnswerAdvisor(vectorStore,
                    SearchRequest.defaults().withTopK(4)))
            .build();
    }

    public String answer(String question) {
        return chatClient.prompt()
            .user(question)
            .call()
            .content();
    }

    // Override SearchRequest per-call via advisor param
    public String answerPrecise(String question) {
        return chatClient.prompt()
            .user(question)
            .advisors(spec -> spec.param(
                QuestionAnswerAdvisor.RETRIEVAL_QUERY_PARAM, question))
            .call()
            .content();
    }
}

RetrievalAugmentationAdvisor — Modular RAG

RetrievalAugmentationAdvisor is the modular, composable RAG advisor introduced in Spring AI 1.x. Unlike QuestionAnswerAdvisor, which is a single monolithic component, RetrievalAugmentationAdvisor accepts pluggable QueryTransformer, DocumentRetriever, DocumentRanker, and AugmentationAdvisor components. This enables advanced RAG patterns such as query rewriting, hypothetical document embedding, and cross-encoder re-ranking without forking the advisor source.

Example

import org.springframework.ai.rag.advisor.RetrievalAugmentationAdvisor;
import org.springframework.ai.rag.retrieval.source.VectorStoreDocumentRetriever;

@Service
public class ModularRagService {

    private final ChatClient chatClient;

    public ModularRagService(ChatClient.Builder builder, VectorStore vectorStore) {
        VectorStoreDocumentRetriever retriever =
            VectorStoreDocumentRetriever.builder()
                .vectorStore(vectorStore)
                .similarityThreshold(0.70)
                .topK(5)
                .build();

        RetrievalAugmentationAdvisor ragAdvisor =
            RetrievalAugmentationAdvisor.builder()
                .documentRetriever(retriever)
                .build();

        this.chatClient = builder
            .defaultAdvisors(ragAdvisor)
            .build();
    }

    public String answer(String question) {
        return chatClient.prompt()
            .user(question)
            .call()
            .content();
    }
}

Query Rewriting with RewriteQueryTransformer

A user's raw query is often too short or ambiguous for high-quality vector search. Query rewriting transforms the query before similarity search to improve recall. RewriteQueryTransformer uses a ChatModel to rewrite the query into a more explicit form optimized for semantic matching. A variant, MultiQueryExpander, generates several different phrasings of the question and merges the results from all variants, boosting coverage at the cost of additional model calls.

Example

import org.springframework.ai.rag.query.transformer.RewriteQueryTransformer;
import org.springframework.ai.rag.query.expander.MultiQueryExpander;

// Simple rewrite — one improved query
RewriteQueryTransformer rewriter = RewriteQueryTransformer.builder()
    .chatClientBuilder(builder)
    .build();

VectorStoreDocumentRetriever retriever =
    VectorStoreDocumentRetriever.builder()
        .vectorStore(vectorStore)
        .topK(5)
        .build();

RetrievalAugmentationAdvisor ragAdvisor =
    RetrievalAugmentationAdvisor.builder()
        .queryTransformers(List.of(rewriter))
        .documentRetriever(retriever)
        .build();

// Multi-query expansion — generates N variants, merges results
MultiQueryExpander expander = MultiQueryExpander.builder()
    .chatClientBuilder(builder)
    .numberOfQueries(3)
    .build();

RetrievalAugmentationAdvisor expandingAdvisor =
    RetrievalAugmentationAdvisor.builder()
        .queryTransformers(List.of(expander))
        .documentRetriever(retriever)
        .build();

Re-Ranking with DocumentRanker

Initial vector similarity retrieval is fast but approximate. Re-ranking applies a more accurate (but slower) scoring model to the top-K candidates to reorder them before injection into the prompt. Spring AI supports re-ranking via the DocumentRanker interface. CohereReranker is the built-in implementation backed by the Cohere Rerank API; custom implementations can wrap any cross-encoder model or scoring function. Re-ranking typically fetches a larger candidate set (e.g. top-20) then re-scores to top-5 for injection.

Dependency (pom.xml)

<dependency>
  <groupId>org.springframework.ai</groupId>
  <artifactId>spring-ai-cohere-spring-boot-starter</artifactId>
</dependency>

Example

import org.springframework.ai.rag.postretrieval.ranking.cohere.CohereReranker;

// application.properties: spring.ai.cohere.api-key=...

@Service
public class ReRankedRagService {

    private final ChatClient chatClient;

    public ReRankedRagService(ChatClient.Builder builder,
                               VectorStore vectorStore,
                               CohereReranker reranker) {
        VectorStoreDocumentRetriever retriever =
            VectorStoreDocumentRetriever.builder()
                .vectorStore(vectorStore)
                .topK(20)  // fetch broader candidate set
                .build();

        RetrievalAugmentationAdvisor ragAdvisor =
            RetrievalAugmentationAdvisor.builder()
                .documentRetriever(retriever)
                .documentRanker(reranker)   // re-rank top-20 to top-5
                .build();

        this.chatClient = builder
            .defaultAdvisors(ragAdvisor)
            .build();
    }
}

Advanced RAG Patterns

Basic vector similarity search is sufficient for many use cases, but demanding applications need higher precision and recall. Advanced patterns include hybrid keyword-plus-vector search, metadata pre-filtering to scope retrieval to relevant document subsets, and chained transformer pipelines that enrich documents with keywords and summaries before indexing. These patterns are composable — you can combine re-ranking, metadata filtering, and query rewriting in a single RetrievalAugmentationAdvisor.

Hybrid Search — Keyword + Vector Combined

Pure vector search excels at semantic matching but can miss exact keywords (product codes, version numbers, proper nouns). Hybrid search combines BM25 keyword scoring with vector cosine similarity, then fuses the ranked lists using reciprocal rank fusion (RRF) or a weighted linear combination. Some vector stores (PGVector with full-text search, Elasticsearch, OpenSearch, Weaviate) support hybrid natively. Spring AI exposes hybrid search through store-specific configuration and the standard SearchRequest API extended with keyword parameters.

Example — PGVector hybrid search

import org.springframework.ai.vectorstore.pgvector.PgVectorStore;
import org.springframework.ai.vectorstore.SearchRequest;

// PgVectorStore supports hybrid via keyword filter on tsvector column
// Configure in application.properties:
// spring.ai.vectorstore.pgvector.index-type=HNSW

// Hybrid search request with metadata keyword prefilter
FilterExpressionBuilder b = new FilterExpressionBuilder();
List<Document> results = vectorStore.similaritySearch(
    SearchRequest.query("spring security oauth2 configuration")
        .withTopK(10)
        .withSimilarityThreshold(0.60)
        .withFilterExpression(
            b.and(
                b.eq("type", "documentation"),
                b.gte("version", "6.0")
            ).build()));

// Elasticsearch store — native hybrid search via knn + query DSL
// Configure via spring.ai.vectorstore.elasticsearch.knn-num-candidates=100
List<Document> esResults = vectorStore.similaritySearch(
    SearchRequest.query("reactive programming patterns")
        .withTopK(5));

Metadata Filtering with FilterExpressionBuilder

Every Document carries a metadata map of arbitrary key-value pairs. At search time, SearchRequest.withFilterExpression() applies a predicate over metadata to limit the search scope before or during similarity scoring. The FilterExpressionBuilder provides a fluent Java DSL for constructing filter expressions that are translated to the native query syntax of each vector store (SQL WHERE clause for PGVector, Weaviate's GraphQL where filter, Pinecone's metadata filter, etc.).

Example

import org.springframework.ai.vectorstore.filter.FilterExpressionBuilder;

FilterExpressionBuilder b = new FilterExpressionBuilder();

// Simple equality filter
List<Document> docs = vectorStore.similaritySearch(
    SearchRequest.query("connection pooling")
        .withTopK(5)
        .withFilterExpression(b.eq("source", "spring-data-reference").build()));

// Range filter — only recent documents
List<Document> recent = vectorStore.similaritySearch(
    SearchRequest.query("auto-configuration changes")
        .withTopK(5)
        .withFilterExpression(b.gte("year", 2024).build()));

// Compound AND filter
List<Document> compound = vectorStore.similaritySearch(
    SearchRequest.query("batch processing")
        .withTopK(8)
        .withFilterExpression(
            b.and(
                b.eq("category", "spring-batch"),
                b.in("version", List.of("5.0", "5.1", "5.2"))
            ).build()));

// Compound OR filter
List<Document> either = vectorStore.similaritySearch(
    SearchRequest.query("security authentication")
        .withTopK(6)
        .withFilterExpression(
            b.or(
                b.eq("category", "spring-security"),
                b.eq("category", "oauth2")
            ).build()));

// Ingest with metadata to enable filtering
Document doc = new Document(
    "Spring Security 6 requires Java 17 and Spring 6.x.",
    Map.of("category", "spring-security", "version", "6.0", "year", 2023));
vectorStore.add(List.of(doc));

DocumentTransformer Chain — Composable ETL

DocumentTransformer is a functional interface (Function<List<Document>, List<Document>>) that transforms a list of documents. Spring AI ships with several implementations: TokenTextSplitter, KeywordMetadataEnricher, SummaryMetadataEnricher, and ContentFormatTransformer. You can chain multiple transformers using standard Java function composition (andThen) or by applying them sequentially. This creates a clean, testable ETL pipeline where each step is independently replaceable.

Example

import org.springframework.ai.transformer.KeywordMetadataEnricher;
import org.springframework.ai.transformer.SummaryMetadataEnricher;
import org.springframework.ai.transformer.splitter.TokenTextSplitter;
import org.springframework.ai.document.DocumentTransformer;

@Service
public class EnrichedIngestionService {

    private final VectorStore vectorStore;
    private final DocumentTransformer pipeline;

    public EnrichedIngestionService(VectorStore vectorStore,
                                     ChatModel chatModel) {
        this.vectorStore = vectorStore;

        // Build a composable transformer chain
        DocumentTransformer splitter = new TokenTextSplitter(500, 100, 5, 10000, true);
        DocumentTransformer keywordEnricher = new KeywordMetadataEnricher(chatModel, 5);
        DocumentTransformer summaryEnricher = new SummaryMetadataEnricher(chatModel,
            List.of(SummaryMetadataEnricher.SummaryType.PREVIOUS,
                     SummaryMetadataEnricher.SummaryType.CURRENT,
                     SummaryMetadataEnricher.SummaryType.NEXT));

        // Chain: split → enrich keywords → enrich summaries
        this.pipeline = splitter
            .andThen(keywordEnricher)
            .andThen(summaryEnricher);
    }

    public void ingest(Resource resource) {
        List<Document> raw = new TextReader(resource).read();
        List<Document> enriched = pipeline.apply(raw);
        vectorStore.add(enriched);
        System.out.printf("Ingested %d enriched chunks%n", enriched.size());
    }
}
