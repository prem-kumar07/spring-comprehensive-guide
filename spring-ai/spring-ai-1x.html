Spring AI 1.x

Spring AI 1.x Spring Boot 3.x baseline • Latest 1.x: 1.1.0 (Jul 2024) • First GA: 1.0.0 (May 2024)

Spring AI 1.x is the first stable generation of the framework, built on Spring Boot 3 and Spring Framework 6. It introduced the portable ChatClient fluent API, a pluggable VectorStore abstraction, the @Tool annotation for function calling (with the tool loop running inside ChatModel), QuestionAnswerAdvisor for RAG, and BeanOutputConverter for structured output. MCP (Model Context Protocol) client and server support was added in 1.1.x. This page covers the 1.x API surface exclusively — see the Spring AI 2.x page for the current major line.

First ChatClient Call (1.x) [Basic]

Inject ChatClient.Builder (auto-configured), build your ChatClient, and call .content() to get a plain String response. This is the canonical 1.x pattern.

Example

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.stereotype.Service;

@Service
public class AssistantService {

    private final ChatClient chatClient;

    public AssistantService(ChatClient.Builder builder) {
        this.chatClient = builder.build();
    }

    public String ask(String question) {
        // In 1.x: call().content() returns the response as a plain String
        return chatClient.prompt()
            .user(question)
            .call()
            .content();
    }
}
1.x vs 2.x In Spring AI 1.x the terminal method is call().content(). Spring AI 2.x renames this to call().text(). The underlying ChatResponse API also changes: use getContent() in 1.x and getText() in 2.x.

Basic Chat — system, user, call [Basic]

The ChatClient fluent API chains system(), user(), and then either call() (blocking) or stream() (reactive). In 1.x, the final accessor for the text is content().

Example

// Simple call with system prompt
String answer = chatClient.prompt()
    .system("You are a concise technical assistant. Answer in bullet points.")
    .user("What are the benefits of virtual threads?")
    .call()
    .content();   // 1.x method — returns String

// Getting the full ChatResponse for metadata (tokens, finish reason)
import org.springframework.ai.chat.model.ChatResponse;

ChatResponse response = chatClient.prompt()
    .user("Summarise Spring AI in one sentence.")
    .call()
    .chatResponse();

// 1.x API: getContent() on the generation output
String text = response.getResult().getOutput().getContent();
int inputTokens  = response.getMetadata().getUsage().getPromptTokens();
int outputTokens = response.getMetadata().getUsage().getGenerationTokens();
getContent() in 1.x AssistantMessage.getContent() is the 1.x method. Spring AI 2.x renames it to getText() across the whole API surface. Keep this in mind when migrating.

Streaming Responses [Intermediate]

Switch from call() to stream() to get a Flux<String> for token-by-token streaming. Useful for long responses or real-time UIs.

Example

import reactor.core.publisher.Flux;

// Stream tokens as they arrive
Flux<String> tokenStream = chatClient.prompt()
    .user("Write a short poem about Java.")
    .stream()
    .content();   // Flux<String> in 1.x

// Collect all tokens and join (blocking — for testing or CLI)
String fullResponse = tokenStream.collectList().block()
    .stream()
    .collect(java.util.stream.Collectors.joining());

// In a Spring MVC SSE endpoint — push tokens to the browser
@GetMapping(value = "/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public Flux<String> streamAnswer(@RequestParam String q) {
    return chatClient.prompt().user(q).stream().content();
}

Chat Memory (1.x) [Intermediate]

Use MessageChatMemoryAdvisor with InMemoryChatMemory to maintain conversation history across calls. Pass a conversationId via advisor parameters to keep sessions isolated.

Example

import org.springframework.ai.chat.client.advisor.MessageChatMemoryAdvisor;
import org.springframework.ai.chat.memory.InMemoryChatMemory;

@Service
public class ChatService {

    private final ChatClient chatClient;
    private final InMemoryChatMemory memory = new InMemoryChatMemory();

    public ChatService(ChatClient.Builder builder) {
        this.chatClient = builder.build();
    }

    public String chat(String sessionId, String userMessage) {
        return chatClient.prompt()
            .user(userMessage)
            .advisors(new MessageChatMemoryAdvisor(memory))
            .advisors(a -> a.param(
                MessageChatMemoryAdvisor.CONVERSATION_ID_KEY, sessionId))
            .call()
            .content();
    }
}

ChatOptions — Per-Call Overrides [Intermediate]

Override model, temperature, max tokens, and other parameters per request using provider-specific ChatOptions. Options set at call time take precedence over global application.properties defaults.

Example

import org.springframework.ai.openai.OpenAiChatOptions;

OpenAiChatOptions options = OpenAiChatOptions.builder()
    .withModel("gpt-4o-mini")
    .withTemperature(0.2)
    .withMaxTokens(512)
    .build();

String response = chatClient.prompt()
    .user("Classify this text: 'Spring AI rocks!'")
    .options(options)
    .call()
    .content();
Provider-agnostic options For provider-portable code, use ChatOptionsBuilder.builder() from spring-ai-core. Provider-specific options (like OpenAiChatOptions) unlock vendor-only features such as structured output modes.

QuestionAnswerAdvisor — 1.x RAG in One Line [Basic]

QuestionAnswerAdvisor is the built-in 1.x advisor for retrieval-augmented generation. It automatically embeds the user's question, retrieves the top-K similar documents from a VectorStore, and appends them to the system context before calling the model.

Dependency

<!-- spring-ai-bom:1.1.0 manages version -->
<dependency>
  <groupId>org.springframework.ai</groupId>
  <artifactId>spring-ai-pgvector-store-spring-boot-starter</artifactId>
</dependency>

Example

import org.springframework.ai.chat.client.advisor.QuestionAnswerAdvisor;
import org.springframework.ai.vectorstore.VectorStore;

@Service
public class KnowledgeBaseService {

    private final ChatClient chatClient;
    private final VectorStore vectorStore;

    public KnowledgeBaseService(ChatClient.Builder builder, VectorStore vectorStore) {
        this.chatClient = builder.build();
        this.vectorStore = vectorStore;
    }

    public String answer(String question) {
        return chatClient.prompt()
            .user(question)
            // QuestionAnswerAdvisor retrieves relevant docs and injects them
            .advisors(new QuestionAnswerAdvisor(vectorStore))
            .call()
            .content();
    }
}
Spring AI 2.x change In Spring AI 2.x, QuestionAnswerAdvisor is replaced by RetrievalAugmentationAdvisor, which offers a modular retrieval pipeline (query rewriting, re-ranking, etc.). In 1.x, QuestionAnswerAdvisor is the recommended and only built-in RAG advisor.

Document Ingestion Pipeline [Intermediate]

Load documents with a DocumentReader, split them with a DocumentTransformer, then store the chunks in a VectorStore. Spring AI auto-embeds each chunk using the configured EmbeddingModel.

Example

import org.springframework.ai.document.Document;
import org.springframework.ai.reader.tika.TikaDocumentReader;
import org.springframework.ai.transformer.splitter.TokenTextSplitter;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.core.io.ClassPathResource;

@Component
public class DocumentIngester {

    private final VectorStore vectorStore;

    public DocumentIngester(VectorStore vectorStore) {
        this.vectorStore = vectorStore;
    }

    public void ingest(String classpathFile) {
        // 1. Read — supports PDF, DOCX, HTML via Apache Tika
        var reader = new TikaDocumentReader(new ClassPathResource(classpathFile));
        List<Document> docs = reader.get();

        // 2. Split into chunks of ~512 tokens with 50-token overlap
        var splitter = new TokenTextSplitter();
        List<Document> chunks = splitter.apply(docs);

        // 3. Embed and store — EmbeddingModel is called automatically
        vectorStore.add(chunks);
    }
}

@Tool — Declaring a Java Method as a Tool [Basic]

Annotate any Spring-managed method with @Tool(description = "...") to expose it as a callable function. The description is sent to the model so it knows when to invoke the tool. In Spring AI 1.x the tool-calling loop (detect → invoke → feed result back) runs inside the ChatModel implementation.

Example

import org.springframework.ai.tool.annotation.Tool;
import org.springframework.stereotype.Service;

@Service
public class WeatherService {

    @Tool(description = "Get the current weather conditions for a city")
    public String getWeather(String city) {
        // Call your weather API here
        return "Sunny, 22°C in " + city;
    }

    @Tool(description = "Convert temperature from Celsius to Fahrenheit")
    public double celsiusToFahrenheit(double celsius) {
        return celsius * 9.0 / 5.0 + 32;
    }
}

// Wire tools into ChatClient by passing the service instance
@Service
public class AssistantService {

    private final ChatClient chatClient;
    private final WeatherService weatherService;

    public String ask(String question) {
        return chatClient.prompt()
            .user(question)
            .tools(weatherService)   // Spring AI discovers @Tool methods via reflection
            .call()
            .content();
    }
}
Tool loop in 1.x is opaque In Spring AI 1.x the tool-calling loop runs inside ChatModel — you cannot intercept individual tool-dispatch cycles from an Advisor. Spring AI 2.x moves this into ToolCallingAdvisor, making the loop observable and composable.

FunctionCallback — Pre-GA / Legacy Style [Intermediate]

Before @Tool was available, tools were registered as FunctionCallback beans implementing java.util.function.Function. This pattern still works in 1.x but @Tool is the preferred approach.

Example

import org.springframework.ai.model.function.FunctionCallback;
import org.springframework.ai.model.function.FunctionCallbackWrapper;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import java.util.function.Function;

// 1. Define the function as a Spring bean
@Configuration
public class FunctionConfig {

    public record StockRequest(String symbol) {}
    public record StockResponse(String symbol, double price) {}

    @Bean
    @Description("Get the current stock price for a given ticker symbol")
    public Function<StockRequest, StockResponse> stockPrice() {
        return req -> new StockResponse(req.symbol(), fetchPrice(req.symbol()));
    }

    private double fetchPrice(String symbol) { return 182.50; }
}

// 2. Reference by bean name at call time
String response = chatClient.prompt()
    .user("What is Apple's stock price?")
    .function("stockPrice")   // bean name matches method name
    .call()
    .content();
Prefer @Tool FunctionCallback / @Bean Function is the pre-GA approach. Use @Tool on service methods for cleaner code in Spring AI 1.x projects.

@ToolParam — Documenting Parameters [Basic]

Add @ToolParam(description = "...") to each parameter so the model receives clear instructions about what values to supply. Without descriptions the model relies solely on the parameter name.

Example

import org.springframework.ai.tool.annotation.Tool;
import org.springframework.ai.tool.annotation.ToolParam;

@Service
public class FlightService {

    @Tool(description = "Search for available flights between two airports")
    public String searchFlights(
            @ToolParam(description = "IATA origin airport code, e.g. LHR") String origin,
            @ToolParam(description = "IATA destination airport code, e.g. JFK") String destination,
            @ToolParam(description = "Departure date in YYYY-MM-DD format") String date) {
        return "3 flights found: " + origin + " → " + destination + " on " + date;
    }
}

Multi-Tool & Parallel Invocations [Intermediate]

Models like GPT-4o can request multiple tools in a single response. Spring AI 1.x detects parallel tool-call requests, dispatches all of them, collects the results, and feeds them back to the model in one batch. The loop repeats until the model stops requesting tools.

Example

// Register multiple @Tool services — model may call any combination
String response = chatClient.prompt()
    .user("What's the weather in London and Paris, and what's Apple's stock price?")
    .tools(weatherService, stockService)  // model decides which tools to invoke
    .call()
    .content();
// Spring AI 1.x handles the multi-step loop automatically inside ChatModel
Loop depth In Spring AI 1.x the default maximum tool-call iterations is determined by the provider implementation. There is no built-in iteration cap exposed as a property in 1.x (Spring AI 2.x adds explicit maxIterations control via ToolCallingManager).

CallAdvisor Interface [Intermediate]

All Spring AI advisors implement CallAdvisor (for blocking) or StreamAdvisor (for reactive). An advisor wraps the request/response pipeline — similar to a servlet filter — and can modify, log, or short-circuit calls. Implement order() to control priority in the chain.

Interface

import org.springframework.ai.chat.client.advisor.api.AdvisedRequest;
import org.springframework.ai.chat.client.advisor.api.AdvisedResponse;
import org.springframework.ai.chat.client.advisor.api.CallAroundAdvisor;
import org.springframework.ai.chat.client.advisor.api.CallAroundAdvisorChain;

public class TimingAdvisor implements CallAroundAdvisor {

    @Override
    public AdvisedResponse aroundCall(AdvisedRequest request,
                                      CallAroundAdvisorChain chain) {
        long start = System.currentTimeMillis();
        AdvisedResponse response = chain.nextAroundCall(request);
        long ms = System.currentTimeMillis() - start;
        System.out.printf("Model call took %d ms%n", ms);
        return response;
    }

    @Override
    public int getOrder() {
        return Ordered.LOWEST_PRECEDENCE; // run last
    }
}

MessageChatMemoryAdvisor [Basic]

Maintains conversation history across calls using a ChatMemory store. By default keeps the last N messages. Use CONVERSATION_ID_KEY to isolate concurrent user sessions.

Example

import org.springframework.ai.chat.client.advisor.MessageChatMemoryAdvisor;
import org.springframework.ai.chat.memory.InMemoryChatMemory;
import static org.springframework.ai.chat.client.advisor.AbstractChatMemoryAdvisor.CONVERSATION_ID_KEY;

InMemoryChatMemory memory = new InMemoryChatMemory();
MessageChatMemoryAdvisor memoryAdvisor = new MessageChatMemoryAdvisor(memory);

// Each user gets their own session via conversationId
String reply = chatClient.prompt()
    .user("My name is Alice")
    .advisors(memoryAdvisor)
    .advisors(a -> a.param(CONVERSATION_ID_KEY, "user-alice-session-42"))
    .call()
    .content();

// Follow-up — history is injected automatically
String reply2 = chatClient.prompt()
    .user("What is my name?")
    .advisors(memoryAdvisor)
    .advisors(a -> a.param(CONVERSATION_ID_KEY, "user-alice-session-42"))
    .call()
    .content(); // → "Your name is Alice."

SimpleLoggerAdvisor [Basic]

Logs the full AdvisedRequest and AdvisedResponse at DEBUG level. Useful during development to inspect what is being sent to and received from the model.

Example

import org.springframework.ai.chat.client.advisor.SimpleLoggerAdvisor;

String response = chatClient.prompt()

SafeGuardAdvisor — Content Filtering [Intermediate]

Rejects requests containing any of a list of sensitive keywords before they reach the model. A lightweight first-line guard — complement with server-side moderation APIs for production use.

Example

import org.springframework.ai.chat.client.advisor.SafeGuardAdvisor;

SafeGuardAdvisor guard = new SafeGuardAdvisor(
    List.of("password", "secret", "credit card", "ssn")
);

String response = chatClient.prompt()
    .user(userInput)
    .advisors(guard)
    .call()
    .content(); // throws if userInput contains a blocked term

Advisor Chain Ordering [Intermediate]

Advisors execute in ascending order() value — lower numbers run first on the way in, and last on the way out (like servlet filters). Use Spring's Ordered constants for clarity.

Recommended ordering for typical setups

// 1 — SafeGuardAdvisor: filter bad input before anything else (HIGHEST priority)
// 2 — MessageChatMemoryAdvisor: inject history before RAG (so context is correct)
// 3 — QuestionAnswerAdvisor: add retrieved docs to context
// 4 — SimpleLoggerAdvisor: log the final assembled request (LOWEST priority in)

chatClient.prompt()
    .user(question)
    .advisors(
        new SafeGuardAdvisor(blockedTerms),           // order: high
        new MessageChatMemoryAdvisor(memory),          // order: mid-high
        new QuestionAnswerAdvisor(vectorStore),        // order: mid-low
        new SimpleLoggerAdvisor()                      // order: low
    )
    .advisors(a -> a.param(CONVERSATION_ID_KEY, sessionId))
    .call()
    .content();
Rule of thumb Security filters first, memory/context injection second, retrieval third, logging last. Advisors that modify the request should run before advisors that read the assembled request.
Added in Spring AI 1.1.x (July 2024) MCP (Model Context Protocol) is an open standard for AI models to discover and invoke tools running in external processes. Spring AI 1.1.x added a client starter (to consume remote MCP servers) and a server starter (to expose your own @Tool beans as an MCP server). In 1.x, every @Tool-annotated bean is automatically exported — no extra annotation required.

MCP Client — Connecting to an External Tool Server [Intermediate]

Add the MCP client starter and configure the server URL. Spring AI discovers available tools from the server at startup and registers them as ToolCallback beans that can be injected into ChatClient.

Dependency

<dependency>
  <groupId>org.springframework.ai</groupId>
  <artifactId>spring-ai-mcp-client-spring-boot-starter</artifactId>
</dependency>

application.properties

# SSE transport — connects to a running MCP server
spring.ai.mcp.client.transport.sse.url=http://localhost:8090/sse
spring.ai.mcp.client.name=my-mcp-client

Usage

import org.springframework.ai.mcp.client.McpToolCallbackProvider;

@Service
public class AgentService {

    private final ChatClient chatClient;
    private final McpToolCallbackProvider mcpTools;

    public AgentService(ChatClient.Builder builder,
                        McpToolCallbackProvider mcpTools) {
        this.chatClient = builder.build();
        this.mcpTools   = mcpTools;
    }

    public String ask(String question) {
        return chatClient.prompt()
            .user(question)
            .tools(mcpTools)   // auto-discovered tools from the MCP server
            .call()
            .content();
    }
}

BeanOutputConverter (1.x) [Basic]

BeanOutputConverter generates a JSON schema from a Java record or class, appends formatting instructions to the prompt, and parses the model's response back to a typed object. This is the primary structured output mechanism in Spring AI 1.x.

Example

import org.springframework.ai.converter.BeanOutputConverter;

// 1. Define your target type as a Java record
record ProductInfo(String name, String category, double price, boolean inStock) {}

// 2. Create the converter
BeanOutputConverter<ProductInfo> converter =
    new BeanOutputConverter<>(ProductInfo.class);

// 3. Get format instructions and append to the prompt
String formatInstructions = converter.getFormat(); // JSON schema + instructions

String rawJson = chatClient.prompt()
    .user("Describe the Apple AirPods Pro. " + formatInstructions)
    .call()
    .content();

// 4. Parse the response into the typed record
ProductInfo product = converter.convert(rawJson);
System.out.println(product.name());    // AirPods Pro
System.out.println(product.price());   // e.g. 249.0
Spring AI 2.x upgrade In Spring AI 2.x you can use chatClient.prompt().user(...).call().entity(ProductInfo.class) directly — the converter is wired in automatically and the self-correcting loop retries on parse failure. In 1.x, call converter.convert() manually.

ListOutputConverter and MapOutputConverter [Basic]

Use ListOutputConverter to get a List<String>, or MapOutputConverter when the response schema is dynamic.

Example

import org.springframework.ai.converter.ListOutputConverter;
import org.springframework.ai.converter.MapOutputConverter;

// List of items
ListOutputConverter listConverter = new ListOutputConverter(new DefaultConversionService());
String raw = chatClient.prompt()
    .user("List 5 Java best practices. " + listConverter.getFormat())
    .call().content();
List<String> items = listConverter.convert(raw);

// Map of key-value pairs
MapOutputConverter mapConverter = new MapOutputConverter();
String rawMap = chatClient.prompt()
    .user("Return the capitals of France, Germany, and Japan as a JSON object. "
          + mapConverter.getFormat())
    .call().content();
Map<String, Object> capitals = mapConverter.convert(rawMap);

Provider-Native JSON Mode [Intermediate]

Force raw JSON output from the model using provider-specific response format options. This bypasses Spring AI's parsing — you receive a raw JSON string and parse it yourself.

Example (OpenAI)

import org.springframework.ai.openai.OpenAiChatOptions;
import org.springframework.ai.openai.api.OpenAiApi.ChatCompletionRequest.ResponseFormat;

OpenAiChatOptions jsonOptions = OpenAiChatOptions.builder()
    .withResponseFormat(ResponseFormat.JSON)
    .build();

String jsonResponse = chatClient.prompt()
    .system("You must respond only with valid JSON.")
    .user("Give me a JSON object with name, version, and language for Spring AI.")
    .options(jsonOptions)
    .call()
    .content();

// Parse manually — e.g. with Jackson
ObjectMapper mapper = new ObjectMapper();
JsonNode node = mapper.readTree(jsonResponse);
String name = node.get("name").asText();
When to use which Use BeanOutputConverter for type-safe deserialization into Java records — it handles schema generation and parsing. Use native JSON mode when you need a raw JSON string or when integrating with a tool that already handles its own parsing.
