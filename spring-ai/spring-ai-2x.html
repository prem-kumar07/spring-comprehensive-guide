Spring AI 2.x

Spring AI 2.x Spring Boot 4 baseline • GA: 2.0.0 (Jun 12, 2026) • Spring Framework 7 required

Spring AI 2.0 (GA June 2026) is the current major release, built on Spring Boot 4 and Spring Framework 7. The biggest architectural shift is moving the tool-calling loop out of ChatModel and into the open advisor chain via ToolCallingAdvisor, making it interceptable and composable. This release also introduces RetrievalAugmentationAdvisor with a modular retrieval pipeline, annotation-driven MCP server authoring (@McpTool, @McpResource, @McpPrompt), self-correcting structured output via .entity(), and adopts JSpecify null-safety annotations throughout.

Spring Boot 4 required Spring AI 2.x requires Spring Boot 4.x (Spring Framework 7, Java 17+). If you are on Spring Boot 3.x, use Spring AI 1.x.

First ChatClient Call (2.x)

Inject ChatClient.Builder, build a client, and call .text() to get the response string. In Spring AI 2.x, text() replaces the 1.x content() method.

Example

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.stereotype.Service;

@Service
public class AssistantService {

    private final ChatClient chatClient;

    public AssistantService(ChatClient.Builder builder) {
        this.chatClient = builder
            .defaultSystem("You are a helpful assistant.")
            .build();
    }

    public String ask(String question) {
        // 2.x: .text() replaces 1.x .content()
        return chatClient.prompt()
            .user(question)
            .call()
            .text();
    }

    public String askWithFullResponse(String question) {
        var response = chatClient.prompt()
            .user(question)
            .call()
            .chatResponse();
        // 2.x: getText() replaces 1.x getContent()
        String text = response.getResult().getOutput().getText();
        String finishReason = response.getResult().getMetadata().getFinishReason();
        return text + " [finished: " + finishReason + "]";
    }
}
API change from 1.x text() / getText() replaces content() / getContent(). The old methods are deprecated in 2.x and will be removed in a future release.

Basic Chat — system, user, call

The fluent ChatClient API is the primary entry point. Set a system prompt for persona, pass the user message, and call .text() for a simple string result.

// Stateless call with inline system prompt
String reply = chatClient.prompt()
    .system("You are a concise technical writer.")
    .user("Explain dependency injection in two sentences.")
    .call()
    .text();

// Access full ChatResponse for metadata
ChatResponse response = chatClient.prompt()
    .user("What is the capital of France?")
    .call()
    .chatResponse();

String text         = response.getResult().getOutput().getText();
String finishReason = response.getResult().getMetadata().getFinishReason();
int promptTokens    = response.getMetadata().getUsage().getPromptTokens();

Streaming

Use .stream().text() to receive a Flux<String> of incremental tokens — useful for displaying output progressively in a UI.

import reactor.core.publisher.Flux;

// Stream tokens as they arrive
Flux<String> tokens = chatClient.prompt()
    .user("Write a short poem about Spring Framework.")
    .stream()
    .text();

// Collect all tokens when you need the full string
String fullText = tokens.collectList().block()
    .stream().collect(java.util.stream.Collectors.joining());

// Stream full ChatResponse objects (for metadata per chunk)
Flux<ChatResponse> responses = chatClient.prompt()
    .user("Tell me a story.")
    .stream()
    .chatResponse();

Chat Memory — Conversation History

MessageChatMemoryAdvisor maintains conversation history per session. The API is unchanged from Spring AI 1.x.

import org.springframework.ai.chat.memory.InMemoryChatMemory;
import org.springframework.ai.chat.client.advisor.MessageChatMemoryAdvisor;

InMemoryChatMemory memory = new InMemoryChatMemory();

ChatClient chatClient = builder
    .defaultAdvisors(new MessageChatMemoryAdvisor(memory))
    .build();

// First turn
String r1 = chatClient.prompt()
    .user("My name is Alice.")
    .advisorParam(MessageChatMemoryAdvisor.CONVERSATION_ID_KEY, "session-42")
    .call().text();

// Second turn — model remembers "Alice"
String r2 = chatClient.prompt()
    .user("What is my name?")
    .advisorParam(MessageChatMemoryAdvisor.CONVERSATION_ID_KEY, "session-42")
    .call().text(); // → "Your name is Alice."

Multimodal Input (Images, Audio)

Pass images or audio alongside text using Media objects in a UserMessage. Only providers that support the modality will process it.

import org.springframework.ai.chat.messages.UserMessage;
import org.springframework.ai.model.Media;
import org.springframework.util.MimeTypeUtils;
import org.springframework.core.io.ClassPathResource;

// Image from classpath resource
var imageResource = new ClassPathResource("images/chart.png");
var media = new Media(MimeTypeUtils.IMAGE_PNG, imageResource);

UserMessage msg = new UserMessage(
    "Describe what you see in this chart.",
    List.of(media)
);

String description = chatClient.prompt()
    .messages(msg)
    .call()
    .text();
Provider support Multimodal input requires a model that supports vision (e.g. GPT-4o, Claude 3, Gemini 1.5 Pro). Passing images to a text-only model throws a provider API error.

Virtual Threads + ChatClient

With spring.threads.virtual.enabled=true (Spring Boot 4 + Java 21), synchronous .call() runs on virtual threads. You get high concurrency without reactive code.

import java.util.concurrent.CompletableFuture;

// Fan out multiple questions concurrently — each runs on a virtual thread
List<String> questions = List.of(
    "Explain CAP theorem",
    "What is eventual consistency?",
    "Define distributed transaction"
);

List<String> answers = questions.stream()
    .map(q -> CompletableFuture.supplyAsync(
        () -> chatClient.prompt().user(q).call().text()))
    .toList()
    .stream()
    .map(CompletableFuture::join)
    .toList();

RetrievalAugmentationAdvisor (2.x RAG)

The 2.x replacement for QuestionAnswerAdvisor. It uses a modular pipeline — QueryTransformer → DocumentRetriever → DocumentPostProcessor — before augmenting the prompt with retrieved context. Each stage is pluggable.

Dependency

<dependency>
  <groupId>org.springframework.ai</groupId>
  <artifactId>spring-ai-pgvector-store-spring-boot-starter</artifactId>
</dependency>

Example

import org.springframework.ai.rag.advisor.RetrievalAugmentationAdvisor;
import org.springframework.ai.rag.retrieval.source.VectorStoreDocumentRetriever;

@Service
public class KnowledgeBaseService {

    private final ChatClient chatClient;
    private final RetrievalAugmentationAdvisor ragAdvisor;

    public KnowledgeBaseService(ChatClient.Builder builder, VectorStore vectorStore) {
        this.ragAdvisor = RetrievalAugmentationAdvisor.builder()
            .documentRetriever(VectorStoreDocumentRetriever.builder()
                .vectorStore(vectorStore)
                .similarityThreshold(0.7)
                .topK(5)
                .build())
            .build();

        this.chatClient = builder.build();
    }

    public String answer(String question) {
        return chatClient.prompt()
            .user(question)
            .advisors(ragAdvisor)
            .call()
            .text();
    }
}
Migration from 1.x QuestionAnswerAdvisor still compiles in 2.x but is deprecated. Replace with RetrievalAugmentationAdvisor for access to query transformation, re-ranking, and the full retrieval pipeline.

Document Ingestion Pipeline

Load documents from any source, split into chunks, embed them, and store in a VectorStore. Run this once (or on a schedule) to build the knowledge base your RAG advisor will query.

import org.springframework.ai.document.Document;
import org.springframework.ai.reader.tika.TikaDocumentReader;
import org.springframework.ai.transformer.splitter.TokenTextSplitter;

@Component
public class DocumentIngestionPipeline {

    private final VectorStore vectorStore;

    public void ingest(Resource pdfResource) {
        // 1. Read documents from PDF
        List<Document> docs = new TikaDocumentReader(pdfResource).get();

        // 2. Split into ~512-token chunks with 64-token overlap
        List<Document> chunks = new TokenTextSplitter(512, 64).apply(docs);

        // 3. Embed and store (EmbeddingModel called automatically by VectorStore)
        vectorStore.add(chunks);
    }
}

Query Transformation (2.x)

RewriteQueryTransformer rewrites a vague or conversational user question into a retrieval-optimised query before hitting the vector store. Improves recall significantly for multi-turn conversations.

import org.springframework.ai.rag.query.transformer.RewriteQueryTransformer;

RetrievalAugmentationAdvisor ragAdvisor = RetrievalAugmentationAdvisor.builder()
    // Rewrite "What about the refund policy?" into a standalone retrieval query
    .queryTransformer(RewriteQueryTransformer.builder()
        .chatClientBuilder(builder)
        .build())
    .documentRetriever(VectorStoreDocumentRetriever.builder()
        .vectorStore(vectorStore)
        .topK(5)
        .build())
    .build();

ToolCallingAdvisor — Tool Loop in the Advisor Chain

In Spring AI 2.x, the tool-calling loop (detect tool call → dispatch → feed result back → repeat) runs as ToolCallingAdvisor in the open advisor chain instead of being hidden inside ChatModel. It is auto-registered when tools are present — no explicit wiring needed for standard use.

// Standard usage — ToolCallingAdvisor is auto-registered
String response = chatClient.prompt()
    .user("What is the weather in London and Berlin?")
    .tools(weatherService)   // ToolCallingAdvisor joins the chain automatically
    .call()
    .text();

// Advanced: configure max iterations explicitly
import org.springframework.ai.chat.client.advisor.ToolCallingAdvisor;

ChatClient chatClient = builder
    .defaultAdvisors(
        ToolCallingAdvisor.builder().maxIterations(10).build(),
        new SimpleLoggerAdvisor()  // sees every tool-call iteration
    )
    .build();
Why this matters Because ToolCallingAdvisor is a regular advisor, a logging or observability advisor placed around it sees every tool-dispatch cycle, enabling per-tool-call tracing. In 1.x this was impossible — the loop was opaque inside the model implementation.

@Tool Annotation (unchanged, works in 2.x)

The @Tool annotation is unchanged from 1.x. Annotate any Spring service method to make it callable by the model.

import org.springframework.ai.tool.annotation.Tool;
import org.springframework.ai.tool.annotation.ToolParam;
import org.springframework.stereotype.Service;

@Service
public class WeatherService {

    @Tool(description = "Get current weather and temperature for a city")
    public WeatherInfo getWeather(
            @ToolParam(description = "City name, e.g. London, Tokyo") String city,
            @ToolParam(description = "Unit: celsius or fahrenheit") String unit) {
        return weatherClient.fetch(city, unit);
    }
}

// Usage
String answer = chatClient.prompt()
    .user("What's the weather in Tokyo in Celsius?")
    .tools(weatherService)
    .call()
    .text();

ToolContext — Injecting Runtime State into Tools

ToolContext is the 2.x mechanism for passing request-scoped state (user ID, tenant, auth token) into tool methods securely — without putting sensitive values in the prompt where the model can see them.

import org.springframework.ai.tool.ToolContext;

@Service
public class OrderService {

    @Tool(description = "Get recent orders for the currently authenticated user")
    public List<Order> getMyOrders(ToolContext ctx) {
        // Retrieve state injected at the call site — not from the prompt
        String userId   = ctx.get("userId", String.class);
        String tenantId = ctx.get("tenantId", String.class);
        return orderRepository.findByUserAndTenant(userId, tenantId);
    }
}

// Call site — inject context map
String response = chatClient.prompt()
    .user("Show me my last 5 orders")
    .tools(orderService)
    .toolContext(Map.of(
        "userId",   currentUser.getId(),
        "tenantId", currentTenant.getId()
    ))
    .call()
    .text();

ToolCallbackProvider — Global Tool Registration

Implement ToolCallbackProvider as a Spring bean to register a set of tools globally. They are available to every ChatClient call without being passed per-request.

import org.springframework.ai.tool.ToolCallbackProvider;
import org.springframework.ai.tool.method.MethodToolCallbackProvider;

@Configuration
public class GlobalToolsConfig {

    // All @Tool methods on weatherService and calendarService are auto-discovered
    @Bean
    public ToolCallbackProvider globalTools(
            WeatherService weatherService,
            CalendarService calendarService) {
        return MethodToolCallbackProvider.builder()
            .toolObjects(weatherService, calendarService)
            .build();
    }
}
Per-call vs global Pass tools via .tools(myService) for request-specific tools (e.g. user-owned resources). Use ToolCallbackProvider beans for shared, stateless utilities available to all requests.

ToolCallingManager — Programmatic Tool Dispatch

For advanced scenarios where you need to resolve and execute tools outside the advisor chain — e.g. in a custom agentic loop — inject ToolCallingManager directly.

import org.springframework.ai.tool.execution.ToolCallingManager;

@Service
public class CustomAgentLoop {

    private final ChatClient chatClient;
    private final ToolCallingManager toolCallingManager;

    public String run(String userMessage) {
        var request = ChatRequest.builder()
            .message(userMessage)
            .tools(myTools)
            .build();

        ChatResponse response = chatClient.call(request);

        // Manually process tool calls if present
        while (response.hasToolCalls()) {
            var toolResults = toolCallingManager.executeToolCalls(request, response);
            response = chatClient.callWithToolResults(request, toolResults);
        }
        return response.getResult().getOutput().getText();
    }
}

Advisor Chain Architecture (2.x)

Advisors wrap the chat call in a chain, from highest to lowest priority. In 2.x, ToolCallingAdvisor joins the chain as a first-class participant — it must have lower priority than RAG and memory advisors so that the augmented prompt reaches the model before tools are dispatched.

import org.springframework.core.Ordered;

ChatClient chatClient = builder
    .defaultAdvisors(
        // Order 0 — executes first (outermost)
        new SimpleLoggerAdvisor(),

        // Order 100 — RAG augmentation before the model sees the prompt
        RetrievalAugmentationAdvisor.builder()
            .documentRetriever(retriever)
            .build(),

        // Order 200 — memory injected after RAG context
        new MessageChatMemoryAdvisor(memory),

        // ToolCallingAdvisor auto-registers at Ordered.LOWEST_PRECEDENCE - 1
        // so it runs after all augmentation advisors
        ToolCallingAdvisor.builder().maxIterations(5).build()
    )
    .build();

RecursiveAdvisor — Self-Refining Loops

Introduced in Spring AI 1.1.x and continued in 2.x. Feeds the model's own response back as context for iterative refinement (e.g. critique → rewrite → critique).

import org.springframework.ai.chat.client.advisor.RecursiveAdvisor;

String refined = chatClient.prompt()
    .user("Write a technical blog post about Spring AI 2.x.")
    .advisors(new RecursiveAdvisor())
    .advisorParam(RecursiveAdvisor.MAX_RECURSION_DEPTH, 3) // max 3 refinement passes
    .call()
    .text();

Writing a Custom Advisor

Implement CallAdvisor to intercept requests and responses. The order() method controls priority — lower numbers run first (outermost).

import org.springframework.ai.chat.client.advisor.api.*;
import org.springframework.core.Ordered;

public class TimingAdvisor implements CallAdvisor {

    @Override
    public AdvisedResponse aroundCall(AdvisedRequest request, CallAroundAdvisorChain chain) {
        long start = System.currentTimeMillis();
        try {
            AdvisedResponse response = chain.nextAroundCall(request);
            long elapsed = System.currentTimeMillis() - start;
            System.out.printf("LLM call took %d ms%n", elapsed);
            return response;
        } catch (Exception ex) {
            long elapsed = System.currentTimeMillis() - start;
            System.out.printf("LLM call failed after %d ms: %s%n", elapsed, ex.getMessage());
            throw ex;
        }
    }

    @Override
    public int getOrder() {
        return Ordered.HIGHEST_PRECEDENCE; // runs outermost — measures total time
    }
}
Spring AI 2.x MCP enhancements Spring AI 2.x adds dedicated MCP server annotations — @McpTool, @McpResource, and @McpPrompt — giving fine-grained control over what is exposed on the MCP surface. In 1.x all @Tool beans were auto-exported; 2.x lets you be selective and exposes MCP capabilities beyond just tools.

@McpTool — Explicit MCP Tool Declaration

@McpTool is the 2.x annotation for explicitly marking a method as an MCP tool. It gives more control than @Tool — you can set the MCP name separately from the Java method name, mark it read-only, or exclude it from auto-export.

import org.springframework.ai.mcp.server.annotation.McpTool;
import org.springframework.stereotype.Component;

@Component
public class InventoryMcpService {

    // Explicit MCP tool name, separate from Java method name
    @McpTool(name = "check-stock",
             description = "Check inventory stock level for a product SKU")
    public StockInfo checkStock(String sku) {
        return inventoryRepository.findBySku(sku)
            .map(StockInfo::from)
            .orElse(StockInfo.outOfStock(sku));
    }

    @McpTool(name = "list-categories",
             description = "List all product categories",
             readOnly = true)
    public List<String> listCategories() {
        return categoryRepository.findAllNames();
    }
}

@McpResource — URI-Addressable Data

New in Spring AI 2.x. Expose a method as an MCP resource — a named, URI-addressable piece of data that MCP clients can read by URI template. Unlike tools, resources represent data, not actions.

import org.springframework.ai.mcp.server.annotation.McpResource;

@Component
public class UserProfileMcpResource {

    @McpResource(
        uri = "resource://users/{userId}",
        description = "Returns the full profile of a user as JSON",
        mimeType = "application/json"
    )
    public String getUserProfile(String userId) {
        User user = userRepository.findById(userId)
            .orElseThrow(() -> new ResourceNotFoundException("User not found: " + userId));
        return objectMapper.writeValueAsString(user);
    }

    @McpResource(
        uri = "resource://users/{userId}/orders",
        description = "Returns order history for a user as JSON"
    )
    public String getUserOrders(String userId) {
        List<Order> orders = orderRepository.findByUserId(userId);
        return objectMapper.writeValueAsString(orders);
    }
}

@McpPrompt — Reusable Prompt Templates

Expose a method as an MCP prompt template. MCP clients call the prompt endpoint with variable values and receive a ready-to-send prompt string — useful for standardising prompt formats across teams or services.

import org.springframework.ai.mcp.server.annotation.McpPrompt;

@Component
public class PromptLibrary {

    @McpPrompt(
        name = "summarize-document",
        description = "Generate a summarization prompt for a document on a given topic"
    )
    public String summarizePrompt(String topic, String maxWords) {
        return """
            You are a technical writer. Summarize the following document about %s
            in at most %s words. Be concise and focus on the key points.
            """.formatted(topic, maxWords);
    }

    @McpPrompt(
        name = "code-review",
        description = "Generate a code review prompt for the given language"
    )
    public String codeReviewPrompt(String language, String focusArea) {
        return """
            Review the following %s code. Focus on %s.
            Identify bugs, suggest improvements, and explain your reasoning.
            """.formatted(language, focusArea);
    }
}

.entity() — One-Step Structured Output (2.x)

The 2.x .entity(Class<T>) shortcut combines BeanOutputConverter, JSON schema injection, and response parsing into a single call. The model is instructed to return valid JSON matching your class's schema, and Spring AI parses the result into the target type automatically.

import jakarta.validation.constraints.NotNull;

// 1. Define the target type (record or class)
record ProductInfo(
    String name,
    String category,
    @NotNull Double price,
    boolean inStock
) {}

// 2. Use .entity() — no manual BeanOutputConverter needed
@Service
public class CatalogService {

    private final ChatClient chatClient;

    public ProductInfo describeProduct(String productDescription) {
        return chatClient.prompt()
            .user("Extract product details from: " + productDescription)
            .call()
            .entity(ProductInfo.class);  // parses JSON → ProductInfo automatically
    }

    // List of objects
    public List<ProductInfo> extractMultipleProducts(String text) {
        return chatClient.prompt()
            .user("Extract all products mentioned in: " + text)
            .call()
            .entity(new ParameterizedTypeReference<List<ProductInfo>>() {});
    }
}
Self-correcting loop When the model response doesn't match the expected schema, Spring AI 2.x automatically retries with the schema violation details as feedback, giving the model a chance to correct itself before throwing an exception.

BeanOutputConverter (still supported in 2.x)

The 1.x manual approach still works in 2.x and is useful when you need the raw JSON string alongside the converted object, or when you want to customise the schema.

import org.springframework.ai.converter.BeanOutputConverter;

record SentimentResult(String sentiment, double confidence, String reasoning) {}

BeanOutputConverter<SentimentResult> converter =
    new BeanOutputConverter<>(SentimentResult.class);

String prompt = "Analyse the sentiment of this text and respond as JSON.\n"
    + converter.getFormat()  // appends JSON schema instructions
    + "\n\nText: I absolutely loved the product!";

String rawJson = chatClient.prompt()
    .user(prompt)
    .call()
    .text();

SentimentResult result = converter.convert(rawJson);

MapOutputConverter

Use MapOutputConverter when the output schema is dynamic or not known at compile time. Returns a Map<String, Object>.

import org.springframework.ai.converter.MapOutputConverter;

MapOutputConverter converter = new MapOutputConverter();

String prompt = "List the top 3 programming languages with their key use cases. "
    + converter.getFormat();

String json = chatClient.prompt().user(prompt).call().text();
Map<String, Object> result = converter.convert(json);
// result = {"Python": "data science, scripting", "Java": "enterprise, Android", ...}

Provider-Native JSON Schema Mode

For providers that support structured output natively (OpenAI, Gemini), you can request JSON Schema-constrained output. Combined with .entity(), this gives guaranteed schema conformance at the provider level.

import org.springframework.ai.openai.OpenAiChatOptions;
import org.springframework.ai.openai.api.ResponseFormat;

record FlightInfo(String airline, String flightNumber,
                  String departure, String arrival, double price) {}

FlightInfo flight = chatClient.prompt()
    .user("Find me the cheapest flight from London to New York next Monday")
    .options(OpenAiChatOptions.builder()
        .withResponseFormat(ResponseFormat.JSON_SCHEMA)
        .build())
    .call()
