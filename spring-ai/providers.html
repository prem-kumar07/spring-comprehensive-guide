Spring AI Providers

Spring AI 1.x Spring AI 2.x

Spring AI abstracts AI provider differences behind a uniform ChatModel / ChatClient API. Swapping providers requires only a different starter dependency and a set of spring.ai.<provider>.* properties — no application code changes. This page covers setup, available model IDs, and provider-specific features for OpenAI, Anthropic, Ollama, major cloud providers, and popular third-party APIs.

OpenAI Setup

Add spring-ai-openai-spring-boot-starter to your project. Set your API key via spring.ai.openai.api-key. Spring AI's auto-configuration registers a ChatModel bean backed by the OpenAI API, which is then available to ChatClient.Builder. The default model is gpt-4o; override with spring.ai.openai.chat.options.model.

pom.xml (BOM + Starter)

<dependencyManagement>
  <dependencies>
    <dependency>
      <groupId>org.springframework.ai</groupId>
      <artifactId>spring-ai-bom</artifactId>
      <version>2.0.0</version>
      <type>pom</type>
      <scope>import</scope>
    </dependency>
  </dependencies>
</dependencyManagement>

<dependencies>
  <dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-openai-spring-boot-starter</artifactId>
  </dependency>
</dependencies>

application.properties

spring.ai.openai.api-key=${OPENAI_API_KEY}
spring.ai.openai.chat.options.model=gpt-4o
spring.ai.openai.chat.options.temperature=0.7

Basic ChatClient Call

@Service
public class AiService {
    private final ChatClient chatClient;

    public AiService(ChatClient.Builder builder) {
        this.chatClient = builder
            .defaultSystem("You are a helpful assistant.")
            .build();
    }

    public String ask(String question) {
        return chatClient.prompt()
            .user(question)
            .call()
            .content();
    }
}

OpenAI Model IDs

OpenAI provides a range of GPT-4o family and o-series reasoning models. The gpt-4o and gpt-4o-mini models are multimodal (text + vision). The o1, o1-mini, and o3-mini models are reasoning-optimised and support the reasoningEffort option (Spring AI 2.0+). Set the model globally in properties or per-request via OpenAiChatOptions.

application.properties

# Default model for all calls
spring.ai.openai.chat.options.model=gpt-4o

# Override per environment
# spring.ai.openai.chat.options.model=gpt-4o-mini

OpenAI Vision (GPT-4o)

gpt-4o and gpt-4o-mini support image input. Attach images to a UserMessage as Media objects. Images can be provided as public URLs (the model fetches them) or as base64-encoded local resources (ClassPathResource, FileSystemResource). Multiple images may be included in a single message. The model returns a text description or answer about the image content.

Vision with Image URL

import org.springframework.ai.chat.messages.UserMessage;
import org.springframework.ai.model.Media;
import org.springframework.util.MimeTypeUtils;

UserMessage message = new UserMessage(
    "What objects are visible in this image?",
    List.of(new Media(MimeTypeUtils.IMAGE_JPEG,
        URI.create("https://example.com/photo.jpg"))));

String answer = chatClient.prompt()
    .options(OpenAiChatOptions.builder().model("gpt-4o").build())
    .messages(message)
    .call()
    .content();

Vision with Local Image File

// Base64-encode a local PNG from classpath
Resource diagram = new ClassPathResource("images/architecture.png");

UserMessage visionMsg = new UserMessage(
    "Explain the architecture shown in this diagram.",

String explanation = chatClient.prompt()

OpenAI Reasoning Models (o1 / o3)

The o1, o1-mini, and o3-mini models perform internal chain-of-thought reasoning before producing a response. In Spring AI 2.0+ you can control reasoning depth with the reasoningEffort option (low, medium, high). These models do not support temperature — omit it. Reasoning models are slower and more expensive but significantly more accurate on multi-step math, logic, and coding tasks.

application.properties

spring.ai.openai.chat.options.model=o3-mini
spring.ai.openai.chat.options.reasoning-effort=medium

Per-Request Reasoning Options

import org.springframework.ai.openai.api.OpenAiApi;

String solution = chatClient.prompt()
    .user("Prove that sqrt(2) is irrational.")
    .options(OpenAiChatOptions.builder()
        .model("o3-mini")
        .reasoningEffort(OpenAiApi.ReasoningEffort.HIGH)
        .maxCompletionTokens(4096)
        // Note: temperature is NOT supported for o-series models
        .build())
    .call()
    .content();

OpenAI Function Calling / Tool Use

OpenAI models support function calling (tool use). In Spring AI, annotate a Spring bean method with @Tool (Spring AI 2.0+) or use FunctionCallback to expose it as a callable tool. The model decides when to invoke the function, Spring AI dispatches the call and feeds the result back automatically. Tool use enables retrieval, computation, and side-effects without manual orchestration.

Defining a Tool

import org.springframework.ai.tool.annotation.Tool;

@Component
public class WeatherService {

    @Tool(description = "Get the current weather for a city")
    public String getWeather(String city) {
        // Call a real weather API here
        return "Sunny, 22°C in " + city;
    }
}

// Wire the tool into ChatClient
@Service
public class AssistantService {
    private final ChatClient chatClient;

    public AssistantService(ChatClient.Builder builder,
                            WeatherService weatherService) {
        this.chatClient = builder
            .defaultTools(weatherService)  // register tool bean
            .build();
    }

    public String ask(String question) {
        return chatClient.prompt()
            .user(question)
            .call()
            .content();
    }
}

Anthropic Extended Thinking / Streaming Thinking

Claude 3.7 Sonnet and later models support extended thinking: the model generates internal reasoning tokens before the final answer. In Spring AI 1.1+ / 2.0+, enable this via AnthropicChatOptions.thinkingEnabled(true). When streaming, the Flux<ChatResponse> emits thinking delta chunks (type THINKING) followed by final answer chunks. Extended thinking increases latency and cost but significantly improves accuracy on hard problems.

application.properties

spring.ai.anthropic.chat.options.model=claude-3-7-sonnet-20250219
spring.ai.anthropic.chat.options.thinking.enabled=true
spring.ai.anthropic.chat.options.thinking.budget-tokens=5000

Streaming with Thinking Deltas

import org.springframework.ai.anthropic.AnthropicChatOptions;

Flux<ChatResponse> stream = chatClient.prompt()
    .user("Solve this step by step: What is 47 * 83?")
    .options(AnthropicChatOptions.builder()
        .model("claude-3-7-sonnet-20250219")
        .thinkingEnabled(true)
        .budgetTokens(4096)
        .build())
    .stream()
    .chatResponse();

stream.subscribe(response -> {
    String text = response.getResult().getOutput().getText();
    // Thinking chunks arrive first; final answer chunks follow
    if (text != null && !text.isEmpty()) {
        System.out.print(text);
    }
});

Anthropic Image Input (Claude 3+)

Claude 3 and later models (Haiku, Sonnet, Opus) support image input. Spring AI handles base64 encoding automatically when you provide a Resource. Images may be PNG, JPEG, GIF, or WebP. Provide the image alongside a text prompt in a UserMessage. Claude is particularly strong at reading charts, diagrams, and document images.

    .options(AnthropicChatOptions.builder()

        .build())

    .content();

Anthropic Tool Use

Claude 3 models support tool use (function calling). Register tools the same way as with OpenAI — Spring AI's abstraction handles the provider-specific wire format automatically. Claude may call the tool zero or more times per turn. Spring AI manages the round-trip: it sends tool results back to Claude and returns the final text response to the caller.

Tool Registration (Same API as OpenAI)

@Component
public class DatabaseLookupTool {

    @Tool(description = "Look up a customer record by customer ID")
    public String lookupCustomer(String customerId) {
        // Query your database
        return "{\"name\":\"Alice\", \"plan\":\"pro\", \"since\":\"2023-01\"}";
    }
}

@Service
public class SupportService {
    private final ChatClient chatClient;

    public SupportService(ChatClient.Builder builder,
                          DatabaseLookupTool dbTool) {
        this.chatClient = builder
            .defaultTools(dbTool)
            .build();
    }

    public String handleQuery(String customerId, String question) {
        return chatClient.prompt()
            .system("Use tools to look up customer data before answering.")
            .user("For customer " + customerId + ": " + question)
            .call()
            .content();
    }
}

Ollama Local Setup

Ollama runs open-source LLMs locally with zero cloud dependencies. Install the Ollama CLI, pull a model, then add spring-ai-ollama-spring-boot-starter. Set spring.ai.ollama.base-url to the local Ollama server address (default http://localhost:11434). Ollama is ideal for development, air-gapped deployments, and privacy-sensitive workloads.

Install and Start

# macOS / Linux
curl -fsSL https://ollama.com/install.sh | sh

# Pull a model
ollama pull llama3.2

# Verify it is running
ollama list

pom.xml

<dependencies>
  <dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-ollama-spring-boot-starter</artifactId>
  </dependency>
</dependencies>

application.properties

spring.ai.ollama.base-url=http://localhost:11434
spring.ai.ollama.chat.options.model=llama3.2
spring.ai.ollama.chat.options.temperature=0.7

Ollama Model Pull Commands

Use ollama pull <model> to download a model before Spring AI can use it. Ollama stores models locally and serves them from the same daemon process. Pull the specific variant you need: general chat, embeddings, or vision. Models are identified by name; append a tag for specific sizes (e.g. llama3.2:3b, llama3.2:70b).

Common Pull Commands

# General-purpose chat models
ollama pull llama3.2          # Meta Llama 3.2 (3B default)
ollama pull llama3.2:70b      # 70B parameter variant
ollama pull mistral           # Mistral 7B
ollama pull phi4              # Microsoft Phi-4

# Embedding models
ollama pull nomic-embed-text  # Recommended for RAG pipelines
ollama pull mxbai-embed-large # High-quality embeddings

# Vision / multimodal models
ollama pull llava             # LLaVA (image + text)
ollama pull llava-phi3        # Phi3 + vision
ollama pull moondream         # Small, fast vision model

# List installed models
ollama list

# Remove a model
ollama rm llama3.2

Ollama Embedding for Local RAG

Ollama also serves embedding models via spring.ai.ollama.embedding.options.model. The nomic-embed-text model produces high-quality 768-dimension embeddings suitable for a local RAG pipeline. Spring AI's OllamaEmbeddingModel implements EmbeddingModel, making it a drop-in replacement for cloud embedding models in a VectorStore configuration.

application.properties

spring.ai.ollama.base-url=http://localhost:11434
spring.ai.ollama.embedding.options.model=nomic-embed-text

Local RAG with Ollama Embeddings

// EmbeddingModel is auto-configured from Ollama starter
@Service
public class LocalRagService {
    private final ChatClient chatClient;
    private final VectorStore vectorStore;

    public LocalRagService(ChatClient.Builder builder,
                           VectorStore vectorStore) {
        this.chatClient = builder
            .defaultAdvisors(
                QuestionAnswerAdvisor.builder(vectorStore).build())
            .build();
        this.vectorStore = vectorStore;
    }

    public void ingest(List<Document> docs) {
        vectorStore.add(docs);  // embedded with nomic-embed-text
    }

    public String query(String question) {
        return chatClient.prompt()
            .user(question)
            .call()
            .content();
    }
}

Running Ollama in Docker

Ollama publishes an official Docker image for containerised environments. Mount a host directory for the model cache so models persist across container restarts. In a Docker Compose setup, Spring Boot can reference the Ollama container by service name. Set spring.ai.ollama.base-url to http://ollama:11434 when both services are on the same Docker network. GPU support requires the NVIDIA Container Toolkit.

docker-compose.yml

services:
  ollama:
    image: ollama/ollama:latest
    ports:
      - "11434:11434"
    volumes:
      - ollama-data:/root/.ollama
    # GPU support (requires NVIDIA Container Toolkit)
    # deploy:
    #   resources:
    #     reservations:
    #       devices:
    #         - driver: nvidia
    #           count: 1
    #           capabilities: [gpu]

  spring-app:
    build: .
    environment:
      SPRING_AI_OLLAMA_BASE_URL: http://ollama:11434
      SPRING_AI_OLLAMA_CHAT_OPTIONS_MODEL: llama3.2
    depends_on:
      - ollama

Amazon Bedrock Setup

Amazon Bedrock provides managed access to models from Anthropic (Claude), Amazon (Titan), Meta (Llama), and others. Use spring-ai-bedrock-converse-spring-boot-starter (Spring AI 2.0), which uses the unified Bedrock Converse API. Authenticate via the standard AWS credential chain — environment variables, instance profile, or an explicit key pair. Enable model access in the AWS Bedrock console before first use.

pom.xml

<dependencies>
  <dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-bedrock-converse-spring-boot-starter</artifactId>
  </dependency>
</dependencies>

application.properties

# AWS credentials (or use instance profile / env vars)
spring.ai.bedrock.aws.region=us-east-1
spring.ai.bedrock.aws.access-key=${AWS_ACCESS_KEY_ID}
spring.ai.bedrock.aws.secret-key=${AWS_SECRET_ACCESS_KEY}

# Model to use via Bedrock Converse API
spring.ai.bedrock.converse.chat.options.model=anthropic.claude-3-5-sonnet-20241022-v2:0

Azure OpenAI Setup

Azure OpenAI hosts OpenAI models within Microsoft's cloud infrastructure. Use spring-ai-azure-openai-spring-boot-starter. Unlike the OpenAI starter, you specify an Azure deployment name (not a raw model ID) and your Azure endpoint. API key authentication and Azure Active Directory token authentication are both supported. Azure OpenAI is useful for organisations that require data residency within Azure regions.

pom.xml

<dependencies>

Provider Switching Pattern

The key benefit of Spring AI's abstraction layer is that swapping providers requires zero application code changes. The same ChatClient bean works identically regardless of the underlying provider. To switch providers: remove the current starter dependency, add the new one, update the API key property, and change the model name. Everything else — service classes, advisors, memory, structured output — stays the same.

The Same ChatClient Works with Every Provider

// This service code works with OpenAI, Anthropic, Ollama, or any provider
@Service
public class UniversalAiService {
    private final ChatClient chatClient;
    private final ChatMemory memory = new InMemoryChatMemory();

    public UniversalAiService(ChatClient.Builder builder) {
        this.chatClient = builder
            .defaultSystem("You are a helpful assistant.")
            .defaultAdvisors(new MessageChatMemoryAdvisor(memory))
            .build();
    }

    public String chat(String sessionId, String message) {
        return chatClient.prompt()
            .user(message)
            .advisors(spec -> spec.param(
                MessageChatMemoryAdvisor.CHAT_MEMORY_CONVERSATION_ID_KEY,
                sessionId))
            .call()
            .content();
    }
}

NVIDIA NIM Setup

NVIDIA NIM (NVIDIA Inference Microservices) provides OpenAI-compatible endpoints for a wide range of optimised models including Llama 3, Mistral, and NVIDIA-proprietary models. Because NIM exposes an OpenAI-compatible REST API, use spring-ai-openai-spring-boot-starter with a custom base URL pointing to your NIM instance (cloud or self-hosted). No special NIM starter is needed.

application.properties (NIM Cloud)

# NVIDIA NIM via OpenAI-compatible API

spring.ai.openai.base-url=https://integrate.api.nvidia.com/v1
