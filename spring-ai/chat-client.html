Spring AI ChatClient API

Spring AI 1.x Spring AI 2.x

ChatClient is the primary developer-facing API in Spring AI for interacting with AI chat models. Modeled after Spring's RestClient and WebClient, it provides a fluent builder pattern for constructing prompts, attaching advisors (such as conversation memory), streaming responses reactively, and sending multimodal inputs — all with a consistent API that works across every supported provider.

Creating a ChatClient

ChatClient instances are created via ChatClient.builder(chatModel). You typically call .build() once in a constructor or @Bean method and hold the resulting client as a field. The builder accepts default system text, default options, and default advisors — everything that should apply to every call made through that client. At runtime the builder delegates to the injected ChatModel, so the same ChatClient code works unchanged across providers.

Dependency (pom.xml)

<dependencyManagement>
  <dependencies>
    <dependency>
      <groupId>org.springframework.ai</groupId>
      <artifactId>spring-ai-bom</artifactId>
      <version>1.0.0</version>
      <type>pom</type>
      <scope>import</scope>
    </dependency>
  </dependencies>
</dependencyManagement>

Example

// Manual construction from a ChatModel bean
@Service
public class AssistantService {
    private final ChatClient chatClient;

    public AssistantService(ChatModel chatModel) {
        this.chatClient = ChatClient.builder(chatModel)
            .defaultSystem("You are a helpful assistant.")
            .build();
    }
}

Auto-wiring ChatClient.Builder

Spring AI's auto-configuration registers a ChatClient.Builder bean with prototype scope: every injection point receives a freshly cloned builder instance pre-configured for the auto-detected ChatModel. This is the recommended way to obtain a ChatClient in Spring Boot applications. Simply inject ChatClient.Builder in your constructor, call .build() (optionally chaining defaults), and Spring manages the rest.

Example

@Service
public class ChatService {
    private final ChatClient chatClient;

    // Spring AI auto-configures ChatClient.Builder as a prototype bean
    public ChatService(ChatClient.Builder builder) {
        this.chatClient = builder
            .defaultSystem("You are a concise assistant.")
            .build();
    }

    public String chat(String question) {
        return chatClient.prompt()
            .user(question)
            .call()
            .content();
    }
}

Making a Call — .call().content()

The simplest ChatClient interaction is .prompt().user(text).call().content(), which sends a user message, waits for the model to complete, and returns the response as a plain String. The .call() terminal initiates a blocking, non-streaming request. Chaining .content() extracts just the text; other terminals on the call spec give you richer response objects.

Example

// Minimal blocking call
String answer = chatClient.prompt()
    .user("What are the main features of Spring AI?")
    .call()
    .content();

// With system and user messages
String response = chatClient.prompt()
    .system("Answer in bullet points.")
    .user("List three benefits of reactive programming.")
    .call()
    .content();

System.out.println(response);

Full ChatResponse with Metadata

Calling .call().chatResponse() returns the full ChatResponse object, which carries not just the model output but also token usage, finish reason, and any provider-specific metadata. This is useful when you need to track costs, enforce token budgets, or inspect why a generation ended (e.g. stop token vs. length limit).

ChatResponse response = chatClient.prompt()
    .user("Explain reactive streams in two sentences.")
    .call()
    .chatResponse();

// 1.x: getContent() to extract text
String text = response.getResult().getOutput().getContent();  // getContent() in 1.x

Usage usage = response.getMetadata().getUsage();
System.out.printf("Prompt tokens: %d%n",     usage.getPromptTokens());
System.out.printf("Completion tokens: %d%n", usage.getGenerationTokens());
System.out.printf("Total tokens: %d%n",      usage.getTotalTokens());
ChatResponse response = chatClient.prompt()
    .user("Explain reactive streams in two sentences.")
    .call()
    .chatResponse();

// 2.x: getText() replaces getContent()
String text = response.getResult().getOutput().getText();      // getText() in 2.x

Usage usage = response.getMetadata().getUsage();
System.out.printf("Prompt tokens: %d%n",     usage.getPromptTokens());
System.out.printf("Completion tokens: %d%n", usage.getGenerationTokens());
System.out.printf("Total tokens: %d%n",      usage.getTotalTokens());

// Finish reason (new in 2.x metadata API)
String finishReason = response.getResult().getMetadata().getFinishReason();

ChatOptions — Temperature, Model, Tokens

ChatOptions lets you control inference parameters such as temperature, maxTokens, and model name at either the builder (default) or the per-call level. Provider-specific option classes (e.g. OpenAiChatOptions) extend the base interface and expose additional knobs like topP and frequencyPenalty. Options passed to .options() on a call override the builder defaults for that request only.

Example

// Provider-specific options (OpenAI example)
ChatOptions precise = OpenAiChatOptions.builder()
    .model("gpt-4o")
    .temperature(0.1)   // near-deterministic
    .maxTokens(512)
    .build();

String summary = chatClient.prompt()
    .user("Summarize the Spring AI architecture.")
    .options(precise)
    .call()
    .content();

// Portable options work with any provider
ChatOptions portable = ChatOptionsBuilder.builder()
    .temperature(0.8)
    .build();

String creative = chatClient.prompt()
    .user("Write a haiku about microservices.")
    .options(portable)
    .call()
    .content();

Streaming with .stream().content()

Replacing .call() with .stream() switches from blocking to reactive delivery. .stream().content() returns a Flux<String> that emits each token or chunk as it arrives from the model, rather than waiting for the full completion. Streaming dramatically lowers perceived latency for longer responses. The Reactive stack (spring-boot-starter-webflux) must be on the classpath to use it, even in a standard MVC application that only needs Flux in tests or service layer code.

Dependency (pom.xml)

<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-webflux</artifactId>
</dependency>

Example

// Returns Flux<String> — each element is a partial chunk
Flux<String> stream = chatClient.prompt()
    .user("Tell me a short story about a robot.")
    .stream()
    .content();

// Subscribe and print each chunk
stream.subscribe(chunk -> System.out.print(chunk));

// Or collect to a single String (blocks)
String full = stream.collectList()
    .block()
    .stream()
    .collect(java.util.stream.Collectors.joining());

SSE Streaming in a Spring MVC Controller

A Spring MVC @GetMapping can return Flux<String> directly when the media type is text/event-stream. Spring's WebFlux integration handles the chunked HTTP transfer automatically. Clients (browsers, EventSource API, curl) receive tokens in real time without any long-polling. Spring Boot 3+ supports this in the MVC dispatcher via the Reactor adapter on the classpath.

Example

@RestController
@RequestMapping("/ai")
public class StreamController {

    private final ChatClient chatClient;

    public StreamController(ChatClient.Builder builder) {
        this.chatClient = builder.build();
    }

    @GetMapping(value = "/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public Flux<String> streamResponse(@RequestParam String message) {
        return chatClient.prompt()
            .user(message)
            .stream()
            .content();
    }
}

Per-Chunk ChatResponse via .stream().chatResponse()

Instead of raw text chunks, .stream().chatResponse() returns a Flux<ChatResponse> where every element is a partially populated ChatResponse. This lets you inspect per-chunk metadata such as finish reason or provider-specific deltas while still streaming. The final element in the flux typically carries the usage statistics for the entire generation.

Example

Flux<ChatResponse> responseFlux = chatClient.prompt()
    .user("Explain the CAP theorem.")
    .stream()
    .chatResponse();

responseFlux.subscribe(response -> {
    String chunk = response.getResult().getOutput().getText();
    if (chunk != null) {
        System.out.print(chunk);
    }
    // Last chunk carries usage
    Usage usage = response.getMetadata().getUsage();
    if (usage != null && usage.getTotalTokens() > 0) {
        System.out.printf("%nTotal tokens: %d%n", usage.getTotalTokens());
    }
});

Collecting a Stream to a List or String

Reactive streams are lazy — nothing is sent to the model until a subscriber exists. In service-layer code or tests where you do not need incremental delivery, you can collect the Flux into a Mono<List<String>> with collectList(), or reduce the chunks with reduce(). Both approaches still benefit from lower time-to-first-token because the request is issued before all chunks are collected. Never call .block() inside a reactive pipeline — only do so at the application boundary.

Example

// Collect all chunks into one String (use at boundary only)
String complete = chatClient.prompt()
    .user("What is Project Reactor?")
    .stream()
    .content()
    .reduce("", String::concat)
    .block();

// In a WebFlux handler, return Mono<String> without blocking
@GetMapping("/ai/answer")
public Mono<String> answer(@RequestParam String q) {
    return chatClient.prompt()
        .user(q)
        .stream()
        .content()
        .reduce("", String::concat);
}

InMemoryChatMemory and MessageChatMemoryAdvisor

InMemoryChatMemory is a volatile, in-process store backed by a ConcurrentHashMap. It is ideal for local development and integration tests. MessageChatMemoryAdvisor bridges ChatClient and ChatMemory: before each model call it prepends the stored messages as conversation history; after the call it saves the new user and assistant messages. Add it via ChatClient.Builder.defaultAdvisors() to enable memory globally.

Dependency (pom.xml)

<dependency>
  <groupId>org.springframework.ai</groupId>
  <artifactId>spring-ai-advisors-vector-store</artifactId>
</dependency>

Example

// Create in-memory store and wire the advisor
ChatMemory memory = new InMemoryChatMemory();

ChatClient chatClient = ChatClient.builder(chatModel)
    .defaultAdvisors(new MessageChatMemoryAdvisor(memory))
    .build();

// First turn
String r1 = chatClient.prompt()
    .user("My name is Alice.")
    .call()
    .content();

// Second turn — model remembers "Alice"
String r2 = chatClient.prompt()
    .user("What is my name?")
    .call()
    .content();

System.out.println(r2); // "Your name is Alice."

Isolating Memory with conversationId

When serving multiple users, each conversation must be isolated by a unique ID. Pass the CHAT_MEMORY_CONVERSATION_ID_KEY parameter through the advisor spec on every call. InMemoryChatMemory (and any ChatMemory implementation) partitions history by this key, so user A's messages never bleed into user B's context. A common pattern is to use the authenticated user's ID or a UUID generated at session start.

Example

@Service
public class ChatService {
    private final ChatClient chatClient;
    private final ChatMemory memory = new InMemoryChatMemory();

    public ChatService(ChatClient.Builder builder) {
        this.chatClient = builder
            .defaultAdvisors(new MessageChatMemoryAdvisor(memory))
            .build();
    }

    public String chat(String userId, String message) {
        return chatClient.prompt()
            .user(message)
            .advisors(spec -> spec.param(
                MessageChatMemoryAdvisor.CHAT_MEMORY_CONVERSATION_ID_KEY,
                userId))
            .call()
            .content();
    }
}

Controlling History Window Size

MessageChatMemoryAdvisor accepts an optional history window size parameter that limits how many past messages are prepended to each request. A smaller window reduces token consumption; a larger window gives the model more context. The default is to include all stored messages. When the window is exceeded, the oldest messages are dropped first, keeping the most recent exchanges in context.

Example

// Keep last 10 messages in context (reduces prompt token cost)
int historyWindow = 10;
ChatMemory memory = new InMemoryChatMemory();

ChatClient chatClient = ChatClient.builder(chatModel)
    .defaultAdvisors(
        new MessageChatMemoryAdvisor(memory,
            MessageChatMemoryAdvisor.DEFAULT_CHAT_MEMORY_CONVERSATION_ID,
            historyWindow))
    .build();

// Alternatively set window per-call via advisor parameters
String response = chatClient.prompt()
    .user("Continue our discussion.")
    .advisors(spec -> spec
        .param(MessageChatMemoryAdvisor.CHAT_MEMORY_CONVERSATION_ID_KEY, "user-42")
        .param(MessageChatMemoryAdvisor.CHAT_MEMORY_RETRIEVE_SIZE_KEY, 5))
    .call()
    .content();

VectorStoreChatMemoryAdvisor for Persistent Memory

VectorStoreChatMemoryAdvisor replaces the simple in-memory store with a VectorStore backend (e.g. PGVector, Redis, Pinecone). Unlike message-window memory, it performs a semantic similarity search to retrieve the most relevant past messages for the current query — enabling long-term memory across many sessions without blowing up the context window. Messages are embedded and stored as vectors; retrieval is similarity-based rather than chronological.

Example

// VectorStore bean provided by your chosen store starter
@Service
public class LongTermMemoryService {
    private final ChatClient chatClient;

    public LongTermMemoryService(ChatClient.Builder builder,
                                  VectorStore vectorStore) {
        this.chatClient = builder
            .defaultAdvisors(
                VectorStoreChatMemoryAdvisor.builder(vectorStore)
                    .conversationId("global-memory")
                    .order(Advisor.DEFAULT_CHAT_MEMORY_PRECEDENCE_ORDER)
                    .build())
            .build();
    }

    public String recall(String userId, String query) {
        return chatClient.prompt()
            .user(query)
            .advisors(spec -> spec.param(
                AbstractChatMemoryAdvisor.CHAT_MEMORY_CONVERSATION_ID_KEY,
                userId))
            .call()
            .content();
    }
}

PromptTemplate with Variable Substitution

PromptTemplate uses the {variableName} syntax backed by the StringTemplate (ST4) engine. Call template.create(Map.of("key", "value")) to produce a Prompt object with all placeholders resolved. The resulting Prompt can be passed directly to chatClient.prompt(prompt). This approach is useful when your prompt text lives in a .st resource file or a @Value-injected string, keeping business logic separate from prompt wording.

Example

import org.springframework.ai.chat.prompt.PromptTemplate;
import org.springframework.ai.chat.prompt.Prompt;

// Template with two variables
PromptTemplate template = new PromptTemplate(
    "Explain {concept} in {language} using simple terms.");

Prompt prompt = template.create(
    Map.of("concept", "reactive streams", "language", "English"));

String answer = chatClient.prompt(prompt)
    .call()
    .content();

// Template from classpath resource
@Value("classpath:prompts/explain.st")
private Resource explainPromptResource;

PromptTemplate fileTemplate = new PromptTemplate(explainPromptResource);

Inline Variable Substitution with .param()

The fluent ChatClient API supports inline template variable binding via .user(u -> u.text("...{var}...").param("var", value)) and the equivalent .system() overload. This is a shortcut for PromptTemplate when you want to keep the template string close to the call site. The same StTemplateRenderer resolves the {} placeholders at call time. Multiple params can be chained.

Example

// Inline param substitution on user message
String answer = chatClient.prompt()
    .user(u -> u.text("Translate '{phrase}' from {source} to {target}.")
                .param("phrase", "Hello World")
                .param("source", "English")
                .param("target", "Japanese"))
    .call()
    .content();

// Param substitution on system message
String response = chatClient.prompt()
    .system(s -> s.text("You are a {role} assistant. Respond in {language}.")
                  .param("role", "coding")
                  .param("language", "English"))
    .user("Explain dependency injection.")
    .call()
    .content();

.system() vs .user() — Role Semantics

The .system() call sets the system message: instructions to the model about persona, tone, output format, or constraints. It is processed before user input and generally carries higher trust. The .user() call sets the user message: the actual end-user query or instruction. Most models treat these differently — system instructions are harder to override with prompt injection than user text. Use .system() for application-controlled context and .user() for runtime user input.

Example

// System sets the persona; user provides the query
String answer = chatClient.prompt()
    .system("""
        You are a senior Spring Boot engineer.
        Answer questions with code examples in Java 21.
        Keep answers under 200 words.
        """)
    .user("How do I write a @RestController in Spring Boot?")
    .call()
    .content();

// Default system text at builder level (applies to every call)
ChatClient client = ChatClient.builder(chatModel)
    .defaultSystem("You are a helpful assistant. Be concise.")
    .build();

Per-Call ChatOptions Override

Options set on the ChatClient.Builder become defaults; options passed to .options() on a specific call override those defaults for that request only. This lets you use conservative defaults (low temperature, smaller model) for most calls while escalating to a more capable model for specific tasks — without creating separate ChatClient instances.

Example

// Builder-level defaults: cheap, fast model
ChatClient client = ChatClient.builder(chatModel)
    .defaultOptions(OpenAiChatOptions.builder()
        .model("gpt-4o-mini")
        .temperature(0.5)
        .build())
    .build();

// Most calls use the default
String quickAnswer = client.prompt()
    .user("What day is it?")
    .call()
    .content();

// This call overrides to the full model
String detailedAnswer = client.prompt()
    .user("Analyze the trade-offs between SQL and NoSQL databases.")
    .options(OpenAiChatOptions.builder()
        .model("gpt-4o")
        .temperature(0.2)
        .maxTokens(1024)
        .build())
    .call()
    .content();

Image Input via URL

For models that support vision (GPT-4o, Claude 3+, Gemini 1.5+), you can pass an image URL by creating a Media object with URI.create(url). The Media is attached to a UserMessage alongside the text prompt. The model receives both the image reference and your question and returns a text response describing or reasoning about the image. URL-based media avoids base64 overhead but requires the model to fetch the URL at inference time.

Dependency (pom.xml)

<dependency>
  <groupId>org.springframework.ai</groupId>
  <artifactId>spring-ai-openai-spring-boot-starter</artifactId>
</dependency>

Example

import org.springframework.ai.chat.messages.UserMessage;
import org.springframework.ai.model.Media;
import org.springframework.util.MimeTypeUtils;

// Describe an image from a public URL
UserMessage message = new UserMessage(
    "What is in this image? Describe the main subject.",
    List.of(new Media(MimeTypeUtils.IMAGE_JPEG,
        URI.create("https://upload.wikimedia.org/wikipedia/commons/thumb/4/47/PNG_transparency_demonstration_1.png/280px-PNG_transparency_demonstration_1.png"))));

String description = ChatClient.builder(chatModel)
    .build()
    .prompt()
    .options(OpenAiChatOptions.builder().model("gpt-4o").build())
    .messages(message)
    .call()
    .content();

Image Input via Resource (Local File or Classpath)

When the image is on the local filesystem or in the classpath, pass a Spring Resource (e.g. ClassPathResource) instead of a URI. Spring AI reads the binary content and encodes it as base64 before sending to the provider. This approach works offline and keeps sensitive images out of public URLs. Use MimeTypeUtils.IMAGE_PNG, IMAGE_JPEG, or IMAGE_GIF depending on the file format.

Example

import org.springframework.core.io.ClassPathResource;

// Load image from classpath
Resource imageResource = new ClassPathResource("images/diagram.png");

UserMessage message = new UserMessage(
    "Explain the architecture shown in this diagram.",
    List.of(new Media(MimeTypeUtils.IMAGE_PNG, imageResource)));

ChatClient chatClient = ChatClient.builder(chatModel).build();

String explanation = chatClient.prompt()
    .options(OpenAiChatOptions.builder().model("gpt-4o").build())
    .messages(message)
    .call()
    .content();

// FileSystemResource for external files
Resource externalFile = new FileSystemResource("/tmp/screenshot.png");
UserMessage fileMessage = new UserMessage(
    "Describe any errors visible in this screenshot.",
    List.of(new Media(MimeTypeUtils.IMAGE_PNG, externalFile)));

Audio Input

Some providers (notably OpenAI with gpt-4o-audio-preview) accept audio files alongside or instead of text. Attach audio with MimeTypeUtils.parseMimeType("audio/mp3") or "audio/wav" and a Resource pointing to the audio file. The model can transcribe, summarize, or reason about the audio content. Check provider-specific documentation for supported audio formats and duration limits before relying on this feature in production.

Example

import org.springframework.util.MimeType;

MimeType mp3Type = MimeTypeUtils.parseMimeType("audio/mp3");
Resource audioFile = new ClassPathResource("recordings/meeting.mp3");

UserMessage audioMessage = new UserMessage(
    "Summarize the key action items from this meeting recording.",
    List.of(new Media(mp3Type, audioFile)));

ChatClient chatClient = ChatClient.builder(chatModel).build();

String summary = chatClient.prompt()
    .options(OpenAiChatOptions.builder()
        .model("gpt-4o-audio-preview")
        .build())
    .messages(audioMessage)
    .call()
    .content();

MockChatModel for Unit Tests

Spring AI's test support module provides MockChatModel (and a Mockito-friendly alternative) for unit-testing code that depends on ChatClient or ChatModel without hitting a real API. Inject the mock model into ChatClient.builder(mockModel) to get a fully configured client. The simplest approach uses Mockito to stub chatModel.call(any(Prompt.class)) with a canned ChatResponse.

Dependency (pom.xml — test scope)

<dependency>
  <groupId>org.springframework.ai</groupId>
  <artifactId>spring-ai-test</artifactId>
  <scope>test</scope>
</dependency>

Example

@ExtendWith(MockitoExtension.class)
class AssistantServiceTest {

    @Mock
    ChatModel chatModel;

    @Test
    void shouldReturnModelResponse() {
        // Arrange — stub a fixed ChatResponse
        AssistantMessage assistantMsg = new AssistantMessage("Spring AI is great!");
        ChatResponse stubResponse =
            new ChatResponse(List.of(new Generation(assistantMsg)));
        when(chatModel.call(any(Prompt.class))).thenReturn(stubResponse);

        ChatClient chatClient = ChatClient.builder(chatModel).build();
        AssistantService service = new AssistantService(chatClient);

        // Act
        String result = service.answer("What is Spring AI?");

        // Assert
        assertThat(result).isEqualTo("Spring AI is great!");
    }
}

Asserting Prompt Content with ArgumentCaptor

Use Mockito's ArgumentCaptor<Prompt> to capture the Prompt object that was actually sent to the model. This lets you verify that your service correctly assembled the system message, user message, chat history, and options before delegating to the AI layer — without coupling tests to the response content. Inspect prompt.getInstructions() for the list of Message objects.

Example

@Test
void shouldSendCorrectSystemMessage() {
    // Arrange
    AssistantMessage reply = new AssistantMessage("OK");
    when(chatModel.call(any(Prompt.class)))
        .thenReturn(new ChatResponse(List.of(new Generation(reply))));

    ChatClient chatClient = ChatClient.builder(chatModel)
        .defaultSystem("You are a test assistant.")
        .build();

    // Act
    chatClient.prompt().user("Hello").call().content();

    // Assert — capture the Prompt that reached the model
    ArgumentCaptor<Prompt> captor = ArgumentCaptor.forClass(Prompt.class);
    verify(chatModel).call(captor.capture());

    Prompt captured = captor.getValue();
    List<Message> messages = captured.getInstructions();

    assertThat(messages).anyMatch(m ->
        m.getMessageType() == MessageType.SYSTEM
        && m.getText().contains("test assistant"));
}

Test-Scoped ChatClient.Builder Bean

In Spring Boot integration tests, you can replace the real ChatModel with a mock via a @TestConfiguration class. Spring AI's auto-configuration detects the mock bean and wires it into the auto-configured ChatClient.Builder. Your service beans receive the builder pointing at the mock, so the full auto-wiring path is exercised without making real API calls. Use @MockBean (Spring Boot) or a @TestConfiguration @Bean for the model.

Example

@SpringBootTest
@AutoConfigureMockMvc
class ChatControllerIntegrationTest {

    @MockBean
    ChatModel chatModel;

    @Autowired
    MockMvc mockMvc;

    @BeforeEach
    void setUp() {
        AssistantMessage msg = new AssistantMessage("Mocked response");
        ChatResponse stubbed =
            new ChatResponse(List.of(new Generation(msg)));
        when(chatModel.call(any(Prompt.class))).thenReturn(stubbed);
    }

    @Test
    void endpointReturnsModelContent() throws Exception {
        mockMvc.perform(get("/ai/chat").param("q", "Hello"))
            .andExpect(status().isOk())
            .andExpect(content().string("Mocked response"));
    }
}

Evaluator-Based AI Testing

Spring AI ships an RelevancyEvaluator (and FactCheckingEvaluator) that use a second AI model call to judge whether the primary model's output is relevant to the question. This "LLM-as-judge" approach is useful for regression tests on AI output quality: the evaluator returns a score, and your test asserts the score exceeds a threshold. It is inherently non-deterministic but catches major regressions. Run evaluator tests in a dedicated CI stage with real API credentials, not in every build.

Dependency (pom.xml — test scope)

<dependency>
  <groupId>org.springframework.ai</groupId>
  <artifactId>spring-ai-test</artifactId>
  <scope>test</scope>
</dependency>

Example

@SpringBootTest
class QualityEvaluationTest {

    @Autowired
    ChatClient.Builder builder;

    @Test
    void answerIsRelevantToQuestion() {
        ChatClient client = builder.build();
        String question = "What is Spring AI?";

        String answer = client.prompt()
            .user(question)
            .call()
            .content();

        // Use a second client call to evaluate relevancy
        RelevancyEvaluator evaluator = new RelevancyEvaluator(builder);
        EvaluationRequest evalRequest =
            new EvaluationRequest(question, List.of(), answer);

        EvaluationResponse evalResponse = evaluator.evaluate(evalRequest);
        assertThat(evalResponse.isPass())
            .as("Expected answer to be relevant to the question")
            .isTrue();
    }
}

EmbeddingModel — Text to Numeric Vectors

Beyond ChatModel, Spring AI's second most-used model type is EmbeddingModel. It converts text (or batches of text) into dense numeric vectors (embeddings) that capture semantic meaning. Embeddings are the foundation of RAG: you embed documents at ingestion time and embed the user's query at retrieval time, then find the most similar documents by vector distance. Spring AI provides EmbeddingModel implementations for every major provider (OpenAI, Anthropic, Mistral, Bedrock, Ollama…) and an identical EmbeddingModel API regardless of provider.

Dependency (pom.xml)

<!-- Uses OpenAI's text-embedding-3-small by default -->
<dependency>

@Service
public class SemanticSearchService {

        this.embeddingModel = embeddingModel;
    }

    }

        float[] va = embed(a);
        float[] vb = embed(b);
        return cosineSimilarity(va, vb);  // your own util
    }
}
1.x vs 2.x The EmbeddingModel API is stable across 1.x and 2.x. The only difference: 2.x aligns with JSpecify null-safety annotations. No migration needed for basic embedding usage.

ImageModel — Text-to-Image Generation

Spring AI's ImageModel provides a uniform API for text-to-image generation models such as OpenAI DALL-E 3 and Stability AI. Provide a text prompt and receive a generated image as a URL or base64-encoded bytes. The model, resolution, style, and quality are configured via ImageOptions.

Dependency (pom.xml) — OpenAI DALL-E

<dependency>
  <groupId>org.springframework.ai</groupId>
  <artifactId>spring-ai-openai-spring-boot-starter</artifactId>
</dependency>

application.properties

spring.ai.openai.api-key=${OPENAI_API_KEY}
spring.ai.openai.image.options.model=dall-e-3
spring.ai.openai.image.options.quality=hd
spring.ai.openai.image.options.size=1024x1024

Generate an image

@Service
public class ImageGenerationService {

    private final ImageModel imageModel;

    public ImageGenerationService(ImageModel imageModel) {
        this.imageModel = imageModel;
    }

    public String generateImage(String prompt) {
        ImageOptions options = ImageOptionsBuilder.builder()
            .model("dall-e-3")
            .height(1024)
            .width(1024)
            .build();

        ImagePrompt imagePrompt = new ImagePrompt(prompt, options);
        ImageResponse response = imageModel.call(imagePrompt);

        // Returns a URL (dall-e-3 default) or base64 bytes
        return response.getResult().getOutput().getUrl();
    }
}

// Per-call override — generate a smaller image for a thumbnail
ImageOptions thumbnailOpts = ImageOptionsBuilder.builder()
    .model("dall-e-3")
    .height(256)
    .width(256)
    .build();
String url = imageModel.call(
    new ImagePrompt("A tiny icon of a coffee cup", thumbnailOpts))
    .getResult().getOutput().getUrl();

AudioTranscriptionModel — Speech-to-Text (Whisper)

Spring AI's AudioTranscriptionModel wraps speech-to-text APIs such as OpenAI Whisper. Provide an audio file (MP3, WAV, M4A, WebM…) and receive a text transcript. Unlike multimodal chat input (sending audio to a vision-enabled chat model), AudioTranscriptionModel calls the dedicated transcription endpoint and returns a plain text result.

Dependency (pom.xml)

<dependency>
  <groupId>org.springframework.ai</groupId>
  <artifactId>spring-ai-openai-spring-boot-starter</artifactId>
</dependency>

application.properties

spring.ai.openai.api-key=${OPENAI_API_KEY}
spring.ai.openai.audio.transcription.options.model=whisper-1
spring.ai.openai.audio.transcription.options.language=en
# Response format: json | text | srt | verbose_json | vtt
spring.ai.openai.audio.transcription.options.response-format=text

Transcribe an audio file

@Service
public class TranscriptionService {

    private final AudioTranscriptionModel transcriptionModel;

    public TranscriptionService(AudioTranscriptionModel transcriptionModel) {
        this.transcriptionModel = transcriptionModel;
    }

    public String transcribe(Resource audioFile) {
        AudioTranscriptionOptions options = OpenAiAudioTranscriptionOptions.builder()
            .model("whisper-1")
            .language("en")
            .responseFormat(OpenAiAudioTranscriptionOptions.TranscriptResponseFormat.TEXT)
            .build();

        AudioTranscriptionPrompt prompt = new AudioTranscriptionPrompt(audioFile, options);
        return transcriptionModel.call(prompt).getResult().getOutput();
    }

    // Convenience — transcribe a classpath resource
    public String transcribeClasspath(String path) {
        return transcribe(new ClassPathResource(path));
    }
}

SpeechModel — Text-to-Speech (TTS)

Spring AI's SpeechModel wraps text-to-speech APIs such as OpenAI TTS. Provide a text string and receive synthesized audio as a byte array. Choose a voice, speed, and output format (MP3, AAC, FLAC, WAV, Opus…). The audio can be streamed or written directly to a file.

Dependency (pom.xml)

<dependency>
  <groupId>org.springframework.ai</groupId>
  <artifactId>spring-ai-openai-spring-boot-starter</artifactId>
</dependency>

application.properties

spring.ai.openai.api-key=${OPENAI_API_KEY}
spring.ai.openai.audio.speech.options.model=tts-1
# Voices: alloy | echo | fable | onyx | nova | shimmer
spring.ai.openai.audio.speech.options.voice=alloy
spring.ai.openai.audio.speech.options.response-format=mp3
spring.ai.openai.audio.speech.options.speed=1.0

Synthesize speech and save to file

@Service
public class TextToSpeechService {

    private final OpenAiAudioSpeechModel speechModel;

    public TextToSpeechService(OpenAiAudioSpeechModel speechModel) {
        this.speechModel = speechModel;
    }

    public byte[] synthesize(String text) {
        OpenAiAudioSpeechOptions options = OpenAiAudioSpeechOptions.builder()
            .model("tts-1")
            .voice(OpenAiAudioSpeechOptions.Voice.ALLOY)
            .responseFormat(OpenAiAudioSpeechOptions.AudioResponseFormat.MP3)
            .speed(1.0f)
            .build();

        SpeechPrompt prompt = new SpeechPrompt(text, options);
        return speechModel.call(prompt).getResult().getOutput();
    }
}

// Expose as a Spring MVC download endpoint
@GetMapping(value = "/speech", produces = "audio/mpeg")
public ResponseEntity<byte[]> speech(@RequestParam String text) {
    byte[] audio = textToSpeechService.synthesize(text);
    return ResponseEntity.ok()
        .header(HttpHeaders.CONTENT_DISPOSITION, "attachment; filename=speech.mp3")
        .body(audio);
}
tts-1 vs tts-1-hd tts-1 is optimized for real-time low-latency use. tts-1-hd produces higher-quality audio but has slightly higher latency. Use tts-1-hd for pre-generated narration and tts-1 for interactive assistant responses.
