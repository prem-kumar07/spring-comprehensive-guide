Spring Boot

Spring Boot 3.x Spring Boot 4.x

Spring Boot removes the boilerplate configuration tax of plain Spring Framework by adding three complementary layers on top: auto-configuration that detects what is on the classpath and wires sensible beans automatically, embedded server support (Tomcat, Jetty, or Undertow packaged inside the jar), and opinionated starter dependencies that pull in a curated, tested set of libraries for each feature area. Together these let a team go from zero to a running production application in minutes, without ever touching an XML context file or writing their own DispatcherServlet registration.

Spring Boot also ships with production-ready defaults — health endpoints, metrics via Micrometer, structured logging, and graceful shutdown — all enabled or tunable through a single application.properties (or YAML) file. The framework follows a convention-over-configuration philosophy: the defaults are chosen to work for the majority of applications, but every default can be overridden when your requirements differ.

Spring Boot vs Spring Framework Spring Boot is an opinionated layer that sits on top of Spring Framework, providing auto-configuration and embedded server support to eliminate boilerplate setup — it uses Spring internally and does not replace it; any Spring bean, annotation, or module you already know continues to work exactly the same way.

Version Timeline

Spring Boot has followed a roughly four-year major-version cadence since its first GA release in April 2014, with each major version tracking a new Spring Framework generation and raising the Java baseline.
