Spring Core Framework

Spring 5.3.x EOL Spring 6.2.x Final Branch Spring 7.0.x Current ✓

Spring Framework is a comprehensive programming and configuration model for modern Java-based enterprise applications. At its heart is an Inversion of Control (IoC) container that manages object creation and wiring through Dependency Injection (DI), letting you describe your application's architecture as a graph of loosely-coupled components rather than a tangle of hard-coded new calls and static references.

Beyond the container, Spring provides a consistent abstraction layer over Aspect-Oriented Programming (AOP) — enabling cross-cutting concerns like transactions, security, and logging to be applied declaratively without polluting your business logic. The framework also ships production-ready modules for web MVC and reactive WebFlux, JDBC/ORM data access, messaging, and testing, all sharing the same foundational container and sharing annotations you already know.

Spring's philosophy is non-invasive programming: your application classes do not need to extend Spring base classes or implement Spring interfaces. The framework works alongside your code through configuration and proxying, so your domain objects remain plain Java (POJO) and are easily unit-tested in isolation. This design principle has guided the framework from its origins in Rod Johnson's 2002 book Expert One-on-One J2EE Design and Development all the way to today's Jakarta EE 10 baseline in Spring 6.

Module Architecture

Spring is structured as a set of modules layered on top of the Core Container. Pick only what you need — each module is independently deployable as a Maven/Gradle dependency.

Version Timeline

Spring 5.3.x open-source support ended August 2024 (javax.*, Jakarta EE 8). Spring 6.2.x (final 6th-gen branch, open-source support ended June 2026) requires Java 17+ and uses jakarta.* namespaces. Spring 7.0.x is the current recommended production line — GA since November 2025, also Java 17+, targeting Jakarta EE 11 (Servlet 6.1, JPA 3.2, Bean Validation 3.1) with JSpecify null safety, built-in resilience (@Retryable, @ConcurrencyLimit), API versioning, and Jackson 3.
