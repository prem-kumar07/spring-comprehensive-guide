Spring AOP Deep Dive

Spring 5/6/7

Aspect-Oriented Programming (AOP) separates cross-cutting concerns — logging, security, transactions, caching, metrics — from business logic. Instead of scattering the same boilerplate across dozens of classes, you write it once in an Aspect and declare where it should apply. Spring AOP uses proxies to weave this behaviour at runtime.

Core Concepts

TermDefinitionExample
AspectA module encapsulating a cross-cutting concernA @Aspect class for logging
AdviceAction taken at a join point — the "what"@Before, @Around, @After
PointcutPredicate that matches join points — the "where"execution(* com.example.service.*.*(..))
Join PointA point in execution where advice could be appliedMethod execution (only type in Spring AOP)
TargetThe real object being advisedYour @Service bean
ProxyThe wrapper object Spring creates to apply adviceCGLIB or JDK proxy of your bean
WeavingProcess of linking aspects to target objectsSpring does this at context creation (runtime)

Dependency

Spring AOP is included in spring-context. In Spring Boot, just add the AOP starter — it also enables @EnableAspectJAutoProxy automatically (you don't need to add the annotation yourself in Boot).

<!-- Maven -->
<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-aop</artifactId>
</dependency>
// Gradle
implementation("org.springframework.boot:spring-boot-starter-aop")
// Without Spring Boot — enable manually:
@Configuration
@EnableAspectJAutoProxy
public class AppConfig { }

Your First Aspect

An aspect is a Spring bean annotated with both @Aspect and @Component. @Aspect marks it as an AspectJ aspect; @Component registers it in the application context so Spring can detect it.

import org.aspectj.lang.annotation.*;
import org.aspectj.lang.ProceedingJoinPoint;
import org.springframework.stereotype.Component;

@Aspect
@Component
public class LoggingAspect {

    // Pointcut: any public method in any class under com.example.service
    @Pointcut("execution(public * com.example.service.*.*(..))")
    public void serviceLayer() {}    // empty method — just a named pointcut

    @Before("serviceLayer()")
    public void logBefore(JoinPoint jp) {
        System.out.printf("[BEFORE] %s.%s%n",
            jp.getTarget().getClass().getSimpleName(),
            jp.getSignature().getName());
    }

    @AfterReturning(pointcut = "serviceLayer()", returning = "result")
    public void logAfterReturning(JoinPoint jp, Object result) {
        System.out.printf("[RETURNED] %s → %s%n",
            jp.getSignature().getName(), result);
    }
}

Spring AOP vs AspectJ

Spring AOP is a proxy-based subset of AOP. Full AspectJ supports compile-time or load-time weaving and can intercept constructors, field access, and static methods. Spring AOP only intercepts method execution on Spring-managed beans — which covers 95% of real-world use cases.

Spring AOPFull AspectJ
Weaving timeRuntime (proxy creation)Compile-time or load-time
Join point typesMethod execution onlyMethod, constructor, field, static init, …
Self-invocation❌ Not intercepted✅ Intercepted
Non-Spring objects❌ Only Spring beans✅ Any object
Setup complexityLow (starter + annotation)High (compiler plugin or agent)
PerformanceGood (proxy overhead)Best (bytecode woven in)

@Before

Runs before the method executes. Cannot prevent the method from running (use @Around for that). If @Before advice throws an exception, the target method is not called.

@Before("execution(* com.example.service.*.*(..))")
public void checkAuth(JoinPoint jp) {
    // Runs before every service method
    // Throwing here prevents the target method from executing
    if (!SecurityContextHolder.getContext().getAuthentication().isAuthenticated()) {
        throw new AccessDeniedException("Not authenticated");
    }
}

@After, @AfterReturning, @AfterThrowing

@After is a "finally" block — fires whether the method returned normally or threw. @AfterReturning fires only on normal return and can bind the return value. @AfterThrowing fires only on exception and can bind the exception.

// @After — always fires (like finally)
@After("execution(* com.example.service.*.*(..))")
public void auditAlways(JoinPoint jp) {
    log.info("Method completed: {}", jp.getSignature().toShortString());
}

// @AfterReturning — only on success; 'returning' binds the return value
@AfterReturning(
    pointcut  = "execution(* com.example.service.UserService.find*(..))",
    returning = "result"          // must match parameter name below
)
public void cacheResult(JoinPoint jp, Object result) {
    if (result != null) {
        cache.put(cacheKey(jp), result);
    }
}

// @AfterThrowing — only on exception; 'throwing' binds the exception
@AfterThrowing(
    pointcut  = "execution(* com.example.service.*.*(..))",
    throwing  = "ex"
)
public void logError(JoinPoint jp, Exception ex) {
    log.error("Exception in {}: {}", jp.getSignature().getName(), ex.getMessage());
    // Note: you cannot suppress the exception here — use @Around for that
}

@Around (Most Powerful)

@Around wraps the entire method. You control whether and when to call proceed() — the real method. You can modify arguments, modify the return value, catch and swallow exceptions, add retry logic, or measure elapsed time. The ProceedingJoinPoint is only available in @Around.

@Around("execution(* com.example.service.*.*(..))")
public Object measureTime(ProceedingJoinPoint pjp) throws Throwable {
    long start = System.currentTimeMillis();
    try {
        Object result = pjp.proceed();          // call the real method
        long elapsed = System.currentTimeMillis() - start;
        log.info("{} took {}ms", pjp.getSignature().getName(), elapsed);
        return result;                          // return its result (or modify it)
    } catch (Throwable t) {
        log.error("Failed: {}", pjp.getSignature().getName(), t);
        throw t;                               // re-throw (or return a fallback)
    }
}

// Modify arguments before proceeding
@Around("execution(* com.example.service.UserService.save(..))")
public Object trimArgs(ProceedingJoinPoint pjp) throws Throwable {
    Object[] args = pjp.getArgs();
    if (args[0] instanceof User u) {
        u.setName(u.getName().trim());         // modify in-place
    }
    return pjp.proceed(args);                 // pass modified args
}

// Retry logic
@Around("@annotation(com.example.Retryable)")
public Object retry(ProceedingJoinPoint pjp) throws Throwable {
    int attempts = 3;
    while (attempts-- > 0) {
        try {
            return pjp.proceed();
        } catch (TransientException e) {
            if (attempts == 0) throw e;
            Thread.sleep(200);
        }
    }
    throw new IllegalStateException("unreachable");
}

Advice Execution Order Within One Aspect

When multiple advice types apply to the same method from the same aspect, the execution order is well-defined. @Around is outermost — it wraps everything else.

→ @Around (before proceed)
  → @Before
    → target method executes
  ← @AfterReturning (or @AfterThrowing)
  ← @After
← @Around (after proceed / return result)

execution() — Method Signature Matching

The most common pointcut designator. Matches method executions by return type, class, method name, and parameters.

// Pattern:
// execution([modifiers] return-type [declaring-class].method-name(params) [throws])
//   * = any single token    .. = any number of tokens (in params = any args)

// All public methods in any class
@Pointcut("execution(public * *(..))")

// All methods in UserService (any return type, any params)
@Pointcut("execution(* com.example.service.UserService.*(..))")

// All methods in any class under com.example.service and its sub-packages
@Pointcut("execution(* com.example.service..*.*(..))")

// Methods starting with "get" returning String
@Pointcut("execution(String com.example..*.get*())")

// Methods with exactly one String parameter
@Pointcut("execution(* *.*(String))")

// Methods with a long first param and any remaining params
@Pointcut("execution(* *.*(long, ..))")

// Only void methods
@Pointcut("execution(void com.example.service.*.*(..))")

within() — Type Matching

Matches all join points within a type or package. Simpler than execution() when you want to target an entire class or package without specifying method details.

// All methods in UserService class
@Pointcut("within(com.example.service.UserService)")

// All methods in any class in the service package (not sub-packages)
@Pointcut("within(com.example.service.*)")

// All methods in any class in service package AND sub-packages
@Pointcut("within(com.example.service..*)")

// All methods in classes annotated with @Service
@Pointcut("within(@org.springframework.stereotype.Service *)")

@annotation, @within, @args

Annotation-based pointcuts are very common in Spring — they let you create custom marker annotations and apply advice to anything carrying that annotation. This is how @Transactional and @Cacheable work.

// @annotation: method carries this annotation
@Pointcut("@annotation(org.springframework.transaction.annotation.Transactional)")
public void transactional() {}

// Custom annotation example — create once, use everywhere
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface Auditable { String action() default ""; }

@Pointcut("@annotation(com.example.Auditable)")
public void auditable() {}

@Before("auditable()")
public void audit(JoinPoint jp) {
    Auditable ann = ((MethodSignature) jp.getSignature())
                        .getMethod().getAnnotation(Auditable.class);
    log.info("AUDIT: action={}", ann.action());
}

// @within: class carries the annotation (applies to all methods in class)
@Pointcut("@within(org.springframework.stereotype.Service)")
public void anyServiceBean() {}

// @args: runtime type of the argument carries the annotation
@Pointcut("@args(com.example.Sensitive)")
public void methodWithSensitiveArg() {}

bean(), this(), target(), args()

// bean(): match by Spring bean name (Spring AOP only, not AspectJ)
@Pointcut("bean(userService)")
public void inUserServiceBean() {}

@Pointcut("bean(*Service)")         // wildcard — all beans ending in "Service"
public void inAnyServiceBean() {}

// this(): the proxy type IS-A the given type
@Pointcut("this(com.example.service.UserService)")

// target(): the real object (not proxy) IS-A the given type
@Pointcut("target(com.example.service.UserService)")

// args(): matches by runtime argument types (also used to bind args)
@Pointcut("args(long, ..)")          // first arg is long

Combining Pointcuts

Pointcuts compose with &&, ||, and !. Named pointcuts in @Pointcut methods can be referenced across aspects.

@Aspect
@Component
public class CommonPointcuts {

    @Pointcut("within(com.example.service..*)")
    public void inServiceLayer() {}

    @Pointcut("within(com.example.web..*)")
    public void inWebLayer() {}

    @Pointcut("inServiceLayer() || inWebLayer()")
    public void inApplicationLayer() {}

    @Pointcut("@annotation(com.example.Auditable) && inServiceLayer()")
    public void auditableServiceMethods() {}

    // Exclude a package
    @Pointcut("inApplicationLayer() && !within(com.example.internal..*)")
    public void externalFacing() {}
}

// Reference from another aspect using fully-qualified method name:
@Before("com.example.aspect.CommonPointcuts.inServiceLayer()")
public void log(JoinPoint jp) { ... }

Binding Parameters from Pointcuts

Pointcut designators can bind method arguments, the annotation instance, and the target object into advice parameters — giving you the actual runtime values without reflection.

// Bind annotation instance to advice parameter
@Before("@annotation(auditable)")            // 'auditable' matches param name
public void audit(JoinPoint jp, Auditable auditable) {
    log.info("action={}", auditable.action());    // access annotation attributes
}

// Bind method argument by type (first matching type wins)
@Before("execution(* *(..)) && args(userId, ..)")
public void trackUser(long userId) {
    log.info("Called with userId={}", userId);
}

// Bind target bean (the real object, not the proxy)
@Before("execution(* *(..)) && target(service)")
public void identifyService(UserService service) {
    log.info("service class: {}", service.getClass().getSimpleName());
}

JoinPoint API

JoinPoint is available as the first parameter in @Before, @After, @AfterReturning, and @AfterThrowing. It gives you reflective access to the intercepted method call.

@Before("execution(* com.example.service.*.*(..))")
public void inspect(JoinPoint jp) {

    // Method signature
    Signature sig = jp.getSignature();
    String methodName = sig.getName();                   // "createOrder"
    String className  = sig.getDeclaringTypeName();      // "com.example.service.OrderService"

    // Cast to MethodSignature for full method info
    MethodSignature ms = (MethodSignature) jp.getSignature();
    Method method       = ms.getMethod();
    String[] paramNames = ms.getParameterNames();        // ["order", "customerId"]
    Class returnType = ms.getReturnType();            // Order.class

    // Runtime arguments
    Object[] args = jp.getArgs();                        // actual argument values

    // The proxy object (Spring proxy, not the real bean)
    Object proxy  = jp.getThis();

    // The real target object
    Object target = jp.getTarget();

    // Full string representation
    String full = jp.toLongString();
    // "execution(public Order com.example.service.OrderService.createOrder(Order))"
}

ProceedingJoinPoint (@Around only)

ProceedingJoinPoint extends JoinPoint with the ability to call proceed() — which continues down the interceptor chain to the real method. You can also pass modified arguments via proceed(Object[]).

@Around("execution(* com.example.service.*.*(..))")
public Object around(ProceedingJoinPoint pjp) throws Throwable {

    // All JoinPoint methods are available
    log.info("About to call: {}", pjp.getSignature().getName());

    // Get arguments (immutable view)
    Object[] args = pjp.getArgs();

    // Proceed with original args
    Object result = pjp.proceed();

    // -- OR -- proceed with modified args
    args[0] = modify(args[0]);
    Object result2 = pjp.proceed(args);

    return result;   // must return — @Around controls what the caller receives
}

// Swallow exception (use carefully)
@Around("@annotation(com.example.Swallow)")
public Object swallowExceptions(ProceedingJoinPoint pjp) throws Throwable {
    try {
        return pjp.proceed();
    } catch (Exception e) {
        log.warn("Swallowed exception in {}", pjp.getSignature().getName(), e);
        return null;   // return null / default for void methods too
    }
}

Accessing Annotations Inside Advice

Two ways to read annotation values inside advice — parameter binding (cleaner) and reflection (more flexible).

// Method 1: parameter binding (no reflection needed)
@Around("@annotation(cacheable)")
public Object cacheAround(ProceedingJoinPoint pjp, Cacheable cacheable) throws Throwable {
    String key = cacheable.cacheNames()[0] + ":" + Arrays.toString(pjp.getArgs());
    Object cached = cacheManager.getCache(cacheable.cacheNames()[0]).get(key);
    if (cached != null) return cached;
    Object result = pjp.proceed();
    cacheManager.getCache(cacheable.cacheNames()[0]).put(key, result);
    return result;
}

// Method 2: reflection via MethodSignature
@Before("@annotation(com.example.RateLimit)")
public void rateLimit(JoinPoint jp) {
    Method method = ((MethodSignature) jp.getSignature()).getMethod();
    RateLimit rl  = method.getAnnotation(RateLimit.class);
    rateLimiter.acquire(rl.value());
}

Ordering Multiple Aspects

When multiple aspects apply to the same method, their order matters. Security should check before transactions start; logging should be outermost. Use @Order on the aspect class — lower number = higher priority = outer layer.

@Aspect
@Component
@Order(1)          // outermost — wraps everything below
public class LoggingAspect {
    @Around("com.example.CommonPointcuts.inServiceLayer()")
    public Object log(ProceedingJoinPoint pjp) throws Throwable {
        log.info("→ {}", pjp.getSignature().getName());
        try {
            return pjp.proceed();
        } finally {
            log.info("← {}", pjp.getSignature().getName());
        }
    }
}

@Aspect
@Component
@Order(2)          // inside Logging, outside Security and Transaction
public class MetricsAspect {
    @Around("com.example.CommonPointcuts.inServiceLayer()")
    public Object measure(ProceedingJoinPoint pjp) throws Throwable {
        long t = System.nanoTime();
        try { return pjp.proceed(); }
        finally { metrics.record(System.nanoTime() - t); }
    }
}

@Aspect
@Component
@Order(3)          // innermost (closest to real method)
public class SecurityAspect {
    @Before("com.example.CommonPointcuts.inServiceLayer()")
    public void checkSecurity(JoinPoint jp) {
        // Security check runs last (innermost), just before real method
    }
}
Execution order for a method call:
→ LoggingAspect.@Around (before proceed)     [Order=1, outermost]
  → MetricsAspect.@Around (before proceed)   [Order=2]
    → SecurityAspect.@Before                 [Order=3]
      → real method executes
    ← SecurityAspect.@After (if any)
  ← MetricsAspect.@Around (after proceed)
← LoggingAspect.@Around (after proceed)      [outermost returns]

Advice Order Within One Aspect

When the same aspect has multiple advice methods for the same pointcut, the order within a single aspect is undefined in Spring AOP (depends on JVM method ordering). If the sequence matters, merge them into a single @Around method.

// ❌ Order between these is undefined (both @Before, same aspect)
@Before("inServiceLayer()")
public void log(JoinPoint jp) { ... }

@Before("inServiceLayer()")
public void audit(JoinPoint jp) { ... }

// ✅ Use @Around to guarantee sequence in one aspect
@Around("inServiceLayer()")
public Object logThenAudit(ProceedingJoinPoint pjp) throws Throwable {
    log(pjp);    // always first
    audit(pjp);  // always second
    return pjp.proceed();
}

Scoped Beans and Proxies

When a shorter-scoped bean (request, session) is injected into a longer-scoped bean (singleton), Spring creates a scoped proxy — a special proxy that looks up the real bean from the scope on each call. Enable with @Scope(proxyMode = ScopedProxyMode.TARGET_CLASS).

// Request-scoped bean injected into singleton
@Component
@Scope(value = WebApplicationContext.SCOPE_REQUEST,
       proxyMode = ScopedProxyMode.TARGET_CLASS)  // creates a CGLIB scoped proxy
public class RequestContext {
    private String correlationId = UUID.randomUUID().toString();
    public String getCorrelationId() { return correlationId; }
}

@Service
public class OrderService {
    @Autowired
    private RequestContext ctx;   // injected once — but ctx is a scoped proxy

    public void process() {
        // Each call: proxy looks up the real RequestContext for THIS request
        String id = ctx.getCorrelationId();
    }
}

Pattern: Structured Method Logging

@Aspect
@Component
@Order(1)
public class MethodLoggingAspect {

    private static final Logger log = LoggerFactory.getLogger(MethodLoggingAspect.class);

    @Around("@within(org.springframework.stereotype.Service)")
    public Object logServiceCalls(ProceedingJoinPoint pjp) throws Throwable {
        String method = pjp.getSignature().toShortString();
        log.debug("→ {}, args={}", method, Arrays.toString(pjp.getArgs()));
        long start = System.currentTimeMillis();
        try {
            Object result = pjp.proceed();
            log.debug("← {} [{}ms]", method, System.currentTimeMillis() - start);
            return result;
        } catch (Throwable t) {
            log.error("✗ {} threw {} [{}ms]",
                method, t.getClass().getSimpleName(),
                System.currentTimeMillis() - start);
            throw t;
        }
    }
}

Pattern: Audit Trail with Custom Annotation

// 1. Define the annotation
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface Audit {
    String action();
    String entity() default "";
}

// 2. Use it in business code
@Service
public class AccountService {
    @Audit(action = "DEBIT", entity = "Account")
    public void debit(long accountId, BigDecimal amount) { ... }
}

// 3. Aspect picks it up
@Aspect
@Component
public class AuditAspect {

    @Autowired private AuditLogRepository auditRepo;

    @AfterReturning("@annotation(audit)")
    public void recordAudit(JoinPoint jp, Audit audit) {
        String user = SecurityContextHolder.getContext()
                          .getAuthentication().getName();
        auditRepo.save(AuditLog.builder()
            .user(user)
            .action(audit.action())
            .entity(audit.entity())
            .args(Arrays.toString(jp.getArgs()))
            .timestamp(Instant.now())
            .build());
    }
}

Pattern: Retry with Backoff

@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface Retryable {
    int attempts() default 3;
    long delayMs() default 500;
    Class<? extends Throwable>[] on() default {Exception.class};
}

@Aspect
@Component
public class RetryAspect {

    @Around("@annotation(retryable)")
    public Object retry(ProceedingJoinPoint pjp, Retryable retryable) throws Throwable {
        int attempts = retryable.attempts();
        long delay   = retryable.delayMs();
        Throwable lastException = null;

        for (int i = 0; i < attempts; i++) {
            try {
                return pjp.proceed();
            } catch (Throwable t) {
                if (!isRetryable(t, retryable.on())) throw t;
                lastException = t;
                log.warn("Retry {}/{} for {} due to {}",
                    i + 1, attempts, pjp.getSignature().getName(),
                    t.getClass().getSimpleName());
                if (i < attempts - 1) Thread.sleep(delay * (i + 1)); // exponential
            }
        }
        throw lastException;
    }

    private boolean isRetryable(Throwable t, Class<? extends Throwable>[] types) {
        return Arrays.stream(types).anyMatch(c -> c.isInstance(t));
    }
}

Pattern: Micrometer Metrics

@Aspect
@Component
public class MetricsAspect {

    @Autowired private MeterRegistry registry;

    @Around("@annotation(io.micrometer.core.annotation.Timed)")
    public Object time(ProceedingJoinPoint pjp) throws Throwable {
        // Let Micrometer's @Timed annotation handle itself —
        // but here's how you'd do it manually:
        String name = "method.execution";
        String method = pjp.getSignature().toShortString();
        Timer.Sample sample = Timer.start(registry);
        String status = "success";
        try {
            return pjp.proceed();
        } catch (Throwable t) {
            status = "error";
            throw t;
        } finally {
            sample.stop(Timer.builder(name)
                .tag("method", method)
                .tag("status", status)
                .register(registry));
        }
    }
}

Pattern: Solving Self-Invocation

When method A calls method B in the same class and B has @Transactional or @Cacheable, the advice on B is bypassed (proxy not in the call path). Three clean solutions:

// ❌ Problem: inner call bypasses proxy
@Service
public class OrderService {
    public void processOrder(Order o) {
        saveOrder(o);          // self-call — @Transactional on saveOrder IGNORED
    }

    @Transactional(propagation = REQUIRES_NEW)
    public void saveOrder(Order o) { repo.save(o); }
}

// ✅ Solution 1: Extract to separate bean
@Service
public class OrderPersistenceService {
    @Transactional(propagation = REQUIRES_NEW)
    public void saveOrder(Order o) { repo.save(o); }
}

@Service
public class OrderService {
    @Autowired OrderPersistenceService persistence;
    public void processOrder(Order o) {
        persistence.saveOrder(o);   // goes through proxy ✅
    }
}

// ✅ Solution 2: Self-inject (acceptable for small classes)
@Service
public class OrderService {
    @Lazy @Autowired private OrderService self;  // @Lazy breaks circular dep

    public void processOrder(Order o) {
        self.saveOrder(o);    // self is the proxy ✅
    }

    @Transactional(propagation = REQUIRES_NEW)
    public void saveOrder(Order o) { repo.save(o); }
}

// ✅ Solution 3: ApplicationContext.getBean (least favourite — framework coupling)
@Autowired private ApplicationContext ctx;
public void processOrder(Order o) {
    ctx.getBean(OrderService.class).saveOrder(o);
}
